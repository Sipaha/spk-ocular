## Допущения агента (пользователь может поправить)

1. Права выдаёт человек в UI Ocular; агент ничего не запрашивает и сам себе не выдаёт (просить
   доступ из API — не в первой версии).
2. Права общие для всех агентов на машине: сокет доступен только владельцу (0600), граница
   безопасности — пользователь ОС, как у SPK launcher. Агент представляется именем
   (заголовок), имя идёт в журнал — это учёт, не изоляция. Права по агенту/проекту — позже.
3. Выданное право — и есть согласие: запись агента в пределах права выполняется без
   подтверждения на каждый вызов, но тем же безопасным путём, что и у UI (просмотр → запуск с
   `Expect`), и попадает в журнал, видимый в UI.
4. Сокет работает, пока запущено приложение (desktop или browser-режим); нет приложения — нет
   доступа.

## Архитектура

- **Транспорт.** HTTP/1.1 + JSON поверх unix-сокета `~/.spk/ocular/agent.sock`
  (`$SPK_OCULAR_HOME/agent.sock`; каталог 0700, сокет 0600). Отдельный `http.ServeMux`
  (`internal/agentapi`), не UI-транспорт: нет токена страницы, Origin/Host-стражей, SSE; в нём
  только методы из каталога ниже. Перед `Listen` — попытка `Dial`: отвечает — сокет занят другим
  экземпляром (агентский API не поднимается, в UI — пометка); не отвечает — старый файл
  удаляется. Сокет закрывается и удаляется при выходе.
- **Проверка прав — в `agentapi`, до вызова `api.Service`.** Каждый метод объявляет, какое право
  и на что ему нужно; обработчик сверяет цель, scope, вид и глагол с выданными правами и
  отказывает `403 forbidden` с текстом, что именно не выдано. Списки фильтруются по выданным
  scope-ам (запрос «все namespace-ы» = объединение выданных). Сам `api.Service` не меняется.
- **Хранение.** Права — таблица SQLite `agent_grants` (провайдер, цель, scope, право, вид);
  журнал — `agent_audit` (время, имя агента, метод, цель, scope, объект, итог, код ошибки;
  без тел запросов и без значений секретов), ротация по объёму.

## Модель прав

Право = **(провайдер, цель, scope, глагол, вид)**:
- *цель* — context kubeconfig или Docker-endpoint (как в списке целей UI);
- *scope* — namespace (Kubernetes) / проект (Compose); отдельный псевдо-scope «кластер» для
  объектов без namespace (узлы, namespace-ы, CRD) — выдаётся явно, по умолчанию закрыт;
- *вид* — конкретный вид (`apps/deployments`) или «все виды»;
- *глаголы* (v1):
  - `read` — виды, список объектов, детали и YAML (у Secret — без значений), события,
    «Проблемы», метрики;
  - `logs` — логи pod-ов/контейнеров;
  - `edit` — правка YAML (P9) и значений ConfigMap;
  - `action:<id>` — конкретное действие (`restart`, `scale`, `delete`, `cordon`, `drain`,
    `suspend`, `run`, …; у Compose — `start`/`stop`/`restart`/`remove`);
  - не в v1 (бэклог): значения Secret, exec/терминал, проброс портов.
- Выдача только явная: «все виды» не включает `delete` и другие разрушающие действия — их
  выдают поимённо. Нет прав на цель — цель не видна агенту вовсе.

## Методы (v1)

Все — `POST /v1/<Method>` с JSON-телом (как UI-транспорт), кроме самоописания:
- `GET /v1` — кто это, версия, как пользоваться (коротко), ссылка на методы.
- `GET /v1/methods` — каталог: имя, описание, JSON-схема запроса и ответа, какое право нужно,
  пишет ли метод. Генерируется из тех же Go-типов, что обслуживают вызовы (не расходится).
- `Access` — цели, scope-ы, виды и глаголы, выданные сейчас (пусто без выдачи).
- `ListKinds`, `ListObjects` (снимок строк с колонками, фильтр, лимит, курсор страницы),
  `GetObject` (детали, YAML), `ListEvents`/`Problems`, `GetMetrics`.
- `GetLogs` — хвост N строк / с момента, без потока (поток — позже).
- `PrepareAction` → `RunAction`, `PrepareEdit` → `RunEdit` — тот же контракт, что у UI:
  план с последствиями и `Expect`, запуск только по плану.
- Ошибки — `{code, detail, why}` как у UI (P13): коды `forbidden`, `not_found`, `conflict`, …

## Инструкция для агента

Одна строка для общих инструкций агента (UI даёт кнопку «Скопировать»):

> SPK Ocular (Kubernetes/Docker): `curl -s --unix-socket ~/.spk/ocular/agent.sock http://ocular/v1`
> — описание и список методов; доступ к namespace-ам выдаёт пользователь в Ocular.

## UI

Раздел «Доступ агентов» (меню цели и общий список): по цели — scope-ы с чекбоксами глаголов и
выбором видов/действий; всё пусто по умолчанию; «Отозвать всё». Журнал вызовов агентов с
фильтром. Статус сокета (работает / занят другим экземпляром). Изменение прав действует на
следующий вызов.

## Проверка

- Go: каждая комбинация «право есть/нет» для каждого метода (таблица), фильтрация списков,
  отказ без прав, псевдо-scope «кластер», разрушающие действия не входят в «все виды», журнал
  без секретов; сокет 0600, занятый сокет, удаление старого файла.
- kind: агент по сокету читает выданный namespace, не видит невыданный, делает restart по праву
  и получает `forbidden` без него.
- Desktop: раздел прав в русской раскладке.
