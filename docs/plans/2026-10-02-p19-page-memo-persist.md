# P19 — Снимок страницы цели между запусками (pageMemo в SQLite)

> Для агентов: задачи выполняются по порядку, шаги отмечаются `- [x]`. Каждая задача — отдельные
> коммиты `area: summary`, `make check` зелёный перед коммитом (коммит — только по его коду
> выхода). Каждое исправление и каждая возможность начинаются с теста, который падает без них
> (проверка мутацией на старом коде).

**Цель:** снимок страницы цели из P18 (вид/scope, фильтр, сортировки по видам, строка курсора,
открытые детали и их вкладка, раскрытые группы навигации) переживает перезапуск приложения:
при следующем запуске каждая цель показывает страницу так, как её оставили. Сейчас снимок
живёт только в памяти (`web/src/components/pageMemo.ts`) — любой перезапуск (обновление,
необходимое при активной разработке приложения) стирает рабочее состояние всех целей.

**Почему этот этап (выбор агента, 2026-10-02; ревью недоступно — сессия `ggyxmbt4` в лимитах
API, пользователь велел работать автономно):** это первый пункт блока «Недавние цели —
после P18» бэклога и прямое продолжение только что закрытого P18: тёплое переключение целей
внутри запуска есть, между запусками — нет; история этапа целиком про «переключение без
потерь». Соседние кандидаты крупнее или уже сделаны: restart workload (Deployment/
StatefulSet/DaemonSet) есть с P4 (`actions.go:334` — merge patch `restartedAt`);
настройки `recentTargets/recentIdle` требуют поверхности настроек, которой в приложении нет;
keyring-кэш exec-плагинов — платформенно-сложен; удаление namespace и undo SS/DS — реже
ежедневного восстановления рабочего места.

**Архитектура:** без новых методов API и без изменений сервера. Клиент хранит снимок
целиком в существующем `SetTargetState(provider, target, "pageMemo", json)`
(`internal/api/service.go:274`, значения до 4096 байт — `maxStateValue`) и читает его из
того ответа `GetTargetState`, который Workspace уже получает при монтировании цели.
`kind`/`scope`/`navOpen` персистятся своими ключами с P0/P8 — их не трогаем, добавляем
только `{sorts, page}`. Отметки (P17) по-прежнему никогда не сохраняются: в типе мемо их
нет, тест закрепляет.

**Спецификация:** `docs/specs/2026-09-29-spk-ocular-design.md`; пункт — `docs/backlog.md`
(«Недавние цели — после P18»: «снимок страницы цели в SQLite между запусками»).

## Глобальные ограничения

- Всё из P0–P18 (AGENTS.md «Правила»): никаких фоновых процессов и опросов — запись
  дебаунсом по событию изменения, не таймером «на всякий случай»; credentials не покидают
  kubeconfig/Go; ручные запуски — изолированные HOME/DOCKER_CONFIG/SPK_OCULAR_HOME.
- Только web: Go, транспорты и store не меняются (`maxStateValue` покрыт существующими
  тестами).
- Потеря < 1 с состояния при закрытии вкладки/приложения до срабатывания дебаунса
  допустима — как у существующих записей kind/scope/navOpen. Переключение цели (размонтирование
  Workspace) сбрасывает ожидающую запись немедленно (flush в cleanup).

## Решения P19 (агент, 2026-10-02)

1. **Ключ и формат.** Один ключ `pageMemo` на цель в `target_state`: JSON
   `{"v":1,"sorts":{...},"page":{...}}` (`page` — `PageMemo` из pageMemo.ts). Поле `v` —
   для будущих смен формы. Разбор защитный: не объект / нет нужных полей / чужая `v` —
   как отсутствие ключа, приложение не падает и не «чинит» запись. Почему один ключ, а не
   `page`+`sorts` отдельно: мелочь целиком переписывается (< 1 КиБ), два ключа — два
   запроса и возможна рассинхронизация пары.
2. **Подписка на изменения.** Чистая модель в `pageMemo.ts`: реестр слушателей
   `onMemoChange(target, cb)`, вызов из `remember` и `rememberSort` (не из `forgetPages` —
   тестовый сброс не пишет). Модуль не знает про клиента — его подписывает Workspace.
3. **Запись.** Хук в Workspace (`useMemoPersist`, рядом с pageMemo, `web/src/components/`):
   дебаунс 1 с trailing; сериализация только `{v, sorts, page}` (ui/navOpen живут своими
   ключами); пропуск, если сериализация > 4096 байт (предел сервера) или равна последней
   записанной (защита от петли «загрузили → записали то же»); fire-and-forget
   `.catch(() => {})` — как существующие записи kind/scope/navOpen. Cleanup размонтирования
   (уход на другую цель) сразу сбрасывает ожидающую запись — последнее состояние цели не
   теряется при переключении.
4. **Чтение.** В существующем эффекте загрузки Workspace (который и так читает
   `GetTargetState`, только когда в памяти нет `ui` — память главнее, P18), в том же
   `.then` распарсить `st.pageMemo` и посеять `sorts`/`page` в `memoOf(tkey)`. Страница
   применяет мемо, только если `page.key` совпал с текущей (уже так в ResourcePage) —
   устаревший снимок (вид исчез из каталога и вернулся другим) не применится чужому
   виду/scope. Открытые детали восстанавливаются по `Ref`: объект заменён — существующий
   экран «объекта больше нет».
5. **Границы.** Несколько вкладок browser-режима с одним каталогом данных: последняя
   запись побеждает (target_state — одна строка на ключ); перезаписывается не чаще дебаунса;
   приемлемо, зафиксировано здесь. Сортировки и фильтр — пользовательский текст, секретов
   мемо не содержит (тип: kind/scope/filter/Ref/вкладка); хранится в локальном SQLite как
   и прочий target_state.
6. **Тесты.** Юнит (`pageMemo.test.ts`): подписка зовётся из remember/rememberSort и молчит
   в forgetPages (failing-first). Модуль persist: форма JSON, дебаунс (fake timers), пропуск
   неизменённого, пропуск > 4096 байт, flush в cleanup. Workspace (vitest): восстановление
   фильтра/сортировки из getTargetState; запись pageMemo после изменения фильтра; отметок
   в полезной нагрузке нет; оверсайз-фильтр — pageMemo не пишется. E2E: отдельный playwright
   конфиг без webServer (по образцу synth-конфигa): спека дважды поднимает browser-бинарь
   с одним SPK_OCULAR_HOME — фильтр, сортировка и открытые детали восстановлены после
   перезапуска (спайк фикстур в Task 3; запасной путь — ручная desktop-проверка под Xvfb :77
   со скриншотами в `.agents/tmp/p19/shot/`, записанной в «Итоги»). Go-тестов нет — сервер
   не меняется.
7. **Документы.** AGENTS.md: правило снимка P18 дополнить «персистится в target_state
   (`pageMemo`) между запусками»; статус P19. Бэклог: пункт «снимок страницы… в SQLite»
   закрыт. План — «Итоги».
