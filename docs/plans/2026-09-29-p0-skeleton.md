# P0 — каркас SPK Ocular

> Для агентов: план выполняется задача за задачей, шаги отмечаются `- [x]`.

**Цель:** запускаемое приложение (desktop и browser-режим), которое при старте показывает contexts
из kubeconfig, запоминает выбранный context и живо обновляет список при изменении kubeconfig;
весь инфраструктурный фундамент (API с двумя транспортами, события, SQLite, provider registry,
гейт `make check`) готов для P1.

**Архитектура:** Go-ядро (`internal/*`) за интерфейсом `api.API`; desktop — Wails v3 бинды +
события, browser — `POST /api/<Method>` + SSE. Kubernetes — первый provider, в P0 умеет только
`Discover` (contexts) и `Watch` (изменения kubeconfig).

**Стек:** Go 1.26, client-go v0.37 (`clientcmd`), fsnotify, cobra, modernc SQLite, Wails
`v3.0.0-beta.26`; React 19, Vite 8, TS 6, Tailwind 4, zustand 5, vitest 4, Playwright.

**Спецификация:** `docs/specs/2026-09-29-spk-ocular-design.md`.

## Глобальные ограничения

- Модуль `github.com/spk/spk-ocular`; бинарь `spk-ocular`; env-префикс `SPK_OCULAR_`.
- Данные: `~/.spk/ocular` (`SPK_OCULAR_HOME`), каталог 0700, `ocular.db` 0600.
- `go build ./...` без тега `wails` обязан проходить; desktop — теги `wails gtk3`.
- Версии `github.com/wailsapp/wails/v3` и `@wailsio/runtime` совпадают (`3.0.0-beta.26`).
- Credentials из kubeconfig не попадают в DTO, логи, события, БД.
- Никаких фоновых опросов: изменения kubeconfig — через inotify (fsnotify), не polling.
- Горячие клавиши — по `KeyboardEvent.code`.

## Решения P0 (агент, 2026-09-29; пользователь может пересмотреть)

- **Источники kubeconfig.** Сначала — ровно как kubectl: файлы из `KUBECONFIG` (иначе
  `~/.kube/config`), merge first-wins. Плюс, как в Lens/outwall, — остальные обычные файлы прямо
  в `~/.kube/`, которые разбираются как kubeconfig с хотя бы одним context (у пользователя там
  лежат `SPK-prod-cluster.yaml`, `SPK.ru`, `cloud-clan.conf`, не подключённые через
  `KUBECONFIG`). Не-kubeconfig файлы молча пропускаются. Context из дополнительного файла с
  именем, уже занятым, получает id `<имя> (<файл>)`.
- **Single-instance нет** (несколько окон/экземпляров допустимы; SQLite в WAL переживает).
  D-Bus probe + cut-off сохранены: GLib без таймаута висит на мёртвой шине.
- **Трея и уведомлений нет** — закрытие окна завершает приложение.

## Задачи

### Task 1: Go-фундамент — paths, store, events, core, provider registry
- [x] `paths.Resolve` (`SPK_OCULAR_HOME` или `~/.spk/ocular`), `Ensure` 0700. Тесты: env override, права.
- [x] `store`: одно соединение, WAL, миграции `NNNN_*.sql`, `WithTx`, `GetUIPref/SetUIPref`. Тесты: миграции идемпотентны, prefs round-trip, файл 0600.
- [x] `events`: Emitter (неблокирующий) + Coalescer — порт с тестами.
- [x] `core`: `Target{Provider, ID, Title, Subtitle, Current, Details}`, `Detail`, `Problem`. Типы P1 (`Ref`, `Row`, `Health`, `KindDescriptor`) добавит P1 — вместе с кодом, который их использует.
- [x] `provider`: `Provider{ID, Title, Discover}`, `TargetWatcher{Watch(ctx, onChange)}`, `Registry`. Тест: порядок, дубликаты id.

### Task 2: Kubernetes provider — discovery и watch
- [x] `kubeconfig.go`: `Sources(env, home)` → основной список (KUBECONFIG/`~/.kube/config`) и дополнительные файлы `~/.kube/*`; `Load(sources)` → contexts с файлом-источником, проблемами по файлам, `current-context`.
- [x] Тесты (таблица фикстур): KUBECONFIG из двух файлов (first-wins), отсутствующий файл, битый YAML (проблема, остальные видны), не-kubeconfig в `~/.kube` (молча), дубликат имени из доп. файла, пустая конфигурация. В `Meta` нет токенов/сертификатов.
- [x] `Watch`: fsnotify на каталоги источников, дребезг 300 мс → `onChange`. Тест: запись файла → колбэк.

### Task 3: API и транспорты
- [x] `api.API`: `AppInfo`, `ListTargets`, `SelectTarget`. `ListTargets` → `{groups:[{provider,title,targets,problems}], selected}`; выбор хранится в `ui_prefs`, исчезнувший target → нет выбора. Событие `targets_changed`.
- [x] `transport/http.go` + `guard.go` (порт: bearer, OriginGuard, LoopbackHostGuard, SSE с ping), `wails.go` (тег `wails`).
- [x] Тесты: 401 без токена, 403 чужой Host/Origin, вызов метода, SSE получает `targets_changed`, `SelectTarget` неизвестного → `CodedError{not_found}`.

## Review Focus

1. Битый/частично битый kubeconfig — видны остальные contexts и понятная проблема, приложение не падает.
2. Kubeconfig переписан атомарно (rename) редактором/`kubectl config` — watch не теряет файл.
3. Выбранный context удалён из kubeconfig — выбор сбрасывается без ошибок.
4. Отсутствует `~/.kube` вовсе — пустое состояние с подсказкой, не ошибка.
5. Нет D-Bus/сломан GPU — окно всё равно открывается (probe, `SPK_OCULAR_GPU`).
