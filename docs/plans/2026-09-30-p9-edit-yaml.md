# P9 — редактирование YAML объекта Kubernetes

> Для агентов: задачи выполняются по порядку, шаги отмечаются `- [x]`. Каждая задача — отдельные
> коммиты `area: summary`, `make check` зелёный перед коммитом. Каждое исправление и каждая
> возможность начинаются с теста, который падает без них.

**Цель:** пользователь правит YAML существующего объекта прямо в деталях (как `kubectl edit`
или «Edit» в Lens). Перед записью он видит, **что изменится**: разницу между объектом сейчас и
**ожидаемым** результатом. Там, где сервер умеет dry-run (это доказано до запроса), ожидаемый
результат считает сервер без записи. Тогда видны defaulting и мутации admission, а ошибки
валидации приходят до подтверждения. Где не умеет — результат считается локально и так и
помечен.

Также видны:
- **где** — context, сервер, namespace, вид, имя;
- права;
- предупреждения, в том числе о правках, которые перезапишут чужие изменения, и о
  необратимых последствиях.

Запись идёт только после подтверждения: над подтверждённым объектом (UID), при той версии
(`resourceVersion`), против которой сделан просмотр, одним запросом, без повторов. Если объект
изменился после просмотра, запись отказывает (`conflict`), и пользователь смотрит заново.
Dry-run — предсказание, а не обещание: фактический результат записи сверяется с просмотром, и
расхождение сказано.

**Архитектура:** provider-агностичная возможность сессии `Editor`. Протокол без серверного
состояния:
1. `EditSource` — текст для редактора и подписанная база.
2. `PrepareEdit` — только чтение: разбор, проверки, патч, dry-run или локальное наложение,
   разница, права, предупреждения, подписанный токен записи.
3. Подтверждение в общем UI.
4. `RunEdit` — проверка токена, тот же патч, запись с предусловиями.

Подписывает API-слой ключом процесса (HMAC, как `ConfigRev`). Провайдер отдаёт и принимает
поля токена в открытом виде.

**Спецификация:** `docs/specs/2026-09-29-spk-ocular-design.md`. «Не делаем в MVP» называл
редактирование/apply YAML; MVP завершён (P0–P8), пункт взят из `docs/backlog.md`. «Принципы»:
Read-first, destructive — с подтверждением, все contexts RW без read-only-пометок.

## Глобальные ограничения

- Всё из P0–P8 (AGENTS.md «Правила»). `internal/core`, `internal/api` и общий UI не знают
  Kubernetes: документ — текст, разница — строки до/после, предупреждения — `Message`
  провайдера, опасность — флаг плана.
- Все contexts работают в RW-режиме. Защита — только UX подтверждения. Возможности операции
  ресурса (dry-run, глагол `patch`) — не политика target-а.
- **`PrepareEdit` ничего не меняет.** Изменяющий HTTP-метод (PATCH) уходит при подготовке,
  только если dry-run для этого endpoint-а доказан заранее (решение 7). Отсутствие
  доказательства никогда не проверяется настоящим запросом.
- Ни одной записи без просмотра: `RunEdit` требует токен из `PrepareEdit`. Токен подписан и
  связывает всё, что показано (решение 10). Просмотр без записи («нет изменений», «недоступно»,
  «прав нет») токена не даёт.
- Никаких автоматических повторов записи и отката. Запись — ровно один HTTP-запрос
  (`restWriter` с `MaxRetries(0)`, как в P4).
- Никаких опросов. Изменение объекта во время редактирования видно по уже существующей
  ревизии деталей (`useObjectRevision`).
- У каждого запроса к кластеру свои контекст и таймаут. Права — необязательная часть просмотра
  с дедлайном 5 с, как в P4.
- Значения Secret никогда не показываются и не пишутся из редактора (решение 5).
- Тесты записи против кластера — только kind `ocular-dev`, с той же проверкой kubeconfig, что
  в P4. Реальные кластеры не трогаются.
- CodeMirror остаётся ленивым чанком. Разница — своя функция с ограниченной работой
  (решение 12), без новой зависимости.

## Решения P9 (агент, 2026-09-30; ревизии 2 и 3 по ревью плана Codex)

1. **Объём.** Правка одного существующего объекта из деталей. В бэклог:
   - создание объектов и `apply -f` многодокументного YAML;
   - раскрытие и правка значений Secret;
   - редактирование Compose (его объекты неизменяемы; compose-файлы уже в бэклоге).
2. **Что редактируемо.** Флаг `KindDescriptor.Editable`:
   - описанные виды Kubernetes — все, кроме Events и синтетических (Problems);
   - обнаруженные — если discovery даёт глагол `patch`.

   Глагол говорит, что обслуживается, а не что разрешено: права проверяет SSAR в просмотре.
   О dry-run глагол ничего не говорит (решение 7).
3. **Показанный документ.** Объект как прочитан, без **скрытых путей**:
   - `status`;
   - `metadata.managedFields`;
   - аннотация `kubectl.kubernetes.io/last-applied-configuration`.

   Над YAML — комментарий: эти поля не показаны, и **редактор их не меняет**; сервер и
   admission могут (решение 6).
   `<N bytes>`, как во вьюере. Формат нормализации имеет версию, она входит в базу.
4. **Разбор текста** (свой, поверх узлов `go.yaml.in/yaml/v3`, без потерь). Отказы (`invalid`
   с номером строки):
   - больше одного документа или что-то после него;
   - корень — не отображение;
   - повторяющиеся ключи;
   - ключи — не строки;
   - якоря, псевдонимы и `<<` (ограничение раздувания; в манифестах Kubernetes не нужны);
   - целые вне int64;
   - нечисловые float (`.inf`, `.nan`).

   Скаляры переводятся в JSON по тегу, числа — как литералы (`json.Number`), без
   `float64`-посредника. Предел текста — 3 МБ, глубины — 100.
5. **Secret.** В P9 у Secret правятся только `metadata`: метки, аннотации, финализаторы и т.д.
   - Патч, задевающий `data`, `stringData`, `type` или `immutable`, — отказ: «значения Secret
     здесь не редактируются».
   - Маска `<N bytes>` в любом месте патча — отказ. Это ловит перенос маски в другое поле,
     например в `stringData`.
   - Разница и результат маскируются тем же `maskSecret`.
   - Сообщения сервера об объекте Secret **не показываются**: ни при просмотре, ни при
     ошибке записи. Подстановкой значения не вычистить: webhook может пересказать значение,
     экранировать его или показать часть, а у `RunEdit` есть только маскированный
     `original`. Строковые поля ответа (`message`, `reason`, `details.causes[].field`/
     `.reason`/`.message`) тоже не выводятся как есть: их заполняет webhook, и Kubernetes не
     требует, чтобы там были только значения перечислений. Показываются:
     - класс ошибки;
     - `reason` — только если это **известное** значение `metav1.StatusReason`, и то в виде
       своего локального текста;
     - число причин (`causes`) с известными `CauseType`, своими словами, без `field`;
     - пояснение «сообщение сервера скрыто: оно может содержать значения Secret».

     Нераспознанная строка не печатается никогда.
6. **Патч** — своя функция RFC 7386 diff над `json.Number`-деревьями: `original` →
   `edited`. Потом:
   - **Идентичность.** `apiVersion`, `kind`, `metadata.name`, `namespace` и `uid` в `original`
     и `edited` совпадают с захваченными маршрутом и ссылкой (из подписанной базы), не только
     между собой. Иначе — `invalid` «это другой объект». `resourceVersion` в тексте
     игнорируется: версию ставит провайдер.
   - **Скрытые пути** в `edited` (status, managedFields, last-applied) — отказ. Предок скрытого
     пути, удалённый целиком (например, `metadata.annotations: null` или удалённый блок), не
     уходит как `null`: он разворачивается в удаление **только видимых** ключей из `original`
     (`{"annotations": {"a": null, "b": null}}`).
   - Инвариант проверяется **на итоговом патче и локальном наложении до отправки**: патч не
     трогает скрытые пути и их предков. Ответ сервера (dry-run или запись) этим не
     проверяется: `managedFields` сервер законно переписывает при любом merge patch (новый
     менеджер, время), а admission может менять что угодно. Поэтому заметка редактора —
     «редактор эти поля не меняет», а не «они не изменятся».
   - **Пустой патч** — план «изменений нет», без токена.
   - **Семантика merge patch** сказана в подсказке редактора: `null` удаляет ключ, массивы
     заменяются целиком.
7. **Когда dry-run доказан.** Строка группы не доказательство: APIService может отдать
   агрегированному серверу любую группу-версию, в том числе `v99.networking.k8s.io`.
   Доказательство — одно из трёх, по конкретному маршруту (GVR):
   - **Точный маршрут описанного вида** P1 (`v1/pods`, `apps/v1/deployments`, … — ровно GVR из
     `allKinds`). Это явное допущение: его обслуживает kube-apiserver. Оно не
     распространяется на другие ресурсы и версии той же группы.
   - **APIService группы-версии локальный** (`apiregistration.k8s.io/v1`,
     `<version>.<group>`, `spec.service` пуст). Такую группу-версию обслуживает сам
     kube-apiserver, в том числе CRD, а он dry-run поддерживает (GA 1.18). Одно чтение на GV за
     сессию.
   - **OpenAPI v3 группы-версии** (`/openapi/v3/apis/<g>/<v>`, один раз на GV за сессию): у
     операции PATCH пути ресурса есть параметр `dryRun`, с разрешением `$ref` параметров
     операции и пути. Так делает kubectl (`cli-runtime` `helper.go`: endpoint, игнорирующий
     `dryRun`, **запишет**).

   Ничего не доказано (не прочитано, запрещено, параметра нет) — просмотр делается
   **локальным наложением** патча на текущий объект и помечен «без проверки сервером». План
   опасный, запись возможна после подтверждения. Изменяющих запросов при подготовке — ноль.
8. **Наложение на текущий объект.** `PrepareEdit` читает объект сейчас, строго с UID.
   Заменённый одноимённым — `gone`. Маршрут сверяется, как в P8. Затем:
   - Патч применяется к **текущему** объекту: dry-run с `metadata.uid`/`resourceVersion`
     текущего объекта и `fieldValidation=Strict`, либо локально (решение 7).
   - Разница — «текущий показанный» против «ожидаемого», нормализованных одинаково (решение
     3). `resourceVersion`, `generation` и `managedFields` не показываются.
   - Если версия базы ≠ текущей, в плане предупреждение «объект изменился после открытия
     редактора». Это **не** трёхстороннее слияние: правки кладутся поверх текущего как есть.
   - **Столкновения:** пути патча, где текущее значение отличается от `original`. Сюда входит
     массив, заменяемый целиком, если его изменили после открытия. Они перечисляются в
     предупреждении «ваша правка перезапишет изменения, сделанные после открытия: <пути>», и
     план становится опасным. Изменения других путей после открытия — безвредное наложение:
     о нём только сказано.
9. **Ответы dry-run** (классы):
   - 200 — ожидаемый результат (`Checked`). Это предсказание: webhook-и, внешние данные и
     случайность могут дать при записи другое.
   - 400/422 (валидация, строгая проверка полей, отказ webhook-а) — `Unavailable` с сообщением
     сервера, без токена. Исключение — ответ о webhook-е, не поддерживающем dry-run
     (`does not support dry run` в причине admission). Только он даёт локальное наложение
     (решение 7) с предупреждением, что проверка невозможна.
   - 403 — `Unavailable` с сообщением: это не обязательно RBAC, admission тоже отказывает 403.
     Права показывает отдельный SSAR.
   - 409 — объект изменился во время подготовки: `conflict` «посмотрите заново».
   - 404 — `gone`.
   - Таймаут, 5xx, обрыв — ошибка подготовки, не план.
10. **Токены** — подписанные структуры: поля провайдера + HMAC API-слоя, как `ConfigRev`. Не
    `actionExpect` P4: тот — неподписанный отпечаток.
    - **База** (`EditSource`): маршрут (GVR + scope), namespace, имя, UID, `resourceVersion`,
      SHA-256 канонического показанного документа, версия нормализации, `ConfigRev`.
      `PrepareEdit` проверяет подпись и хэш присланного `original`. Не совпало —
      `bad_request`.
    - **Запись** (`PrepareEdit`, только у плана, по которому можно писать): маршрут,
      namespace, имя, UID, **версия текущего объекта** (против неё просмотр), SHA-256
      канонического итогового патча (после развёртки решения 6), режим (`checked`/`local`),
      `ConfigRev`.
    - `RunEdit` проверяет подпись и `ConfigRev`, пересчитывает патч из `original`/`edited`
      (тем же разбором). Хэш не совпал — `bad_request`. Маршрут каталога сменился —
      `conflict`. Затем один PATCH с `metadata.uid` и `resourceVersion` **из токена**, без
      перечитывания: более новая версия никогда не делает старое подтверждение годным.
    - Ответы записи: 409 → `conflict` «изменился после просмотра — посмотрите заново»; 422/400 →
      `invalid`; 403 → `forbidden`; 404 → `gone`; 5xx, таймаут и обрыв после отправки →
      `unknown` «результат неизвестен — проверьте объект».
    - Результат — «изменения записаны», новая версия и фактический объект (нормализованный и
      маскированный). UI сравнивает его с ожидаемым и говорит о расхождении («сервер
      изменил результат при записи»). Повтора и отката нет.
11. **Предупреждения и опасность** (строки провайдера, только обоснованное прочитанным):
    - владелец-контроллер (`ownerReferences.controller`): «контроллер может вернуть изменения»;
    - `app.kubernetes.io/managed-by` и аннотации Helm/Argo CD: «могут быть перезаписаны при
      следующем деплое»;
    - патч трогает `spec.template` workload-а: «запустит rollout»;
    - удаляемые поля (пути с `null` после развёртки) перечислены.

    **Опасный план:**
    - локальное наложение;
    - столкновения (решение 8);
    - снятие финализаторов с объекта, у которого есть `deletionTimestamp` («удаление
      завершится сразу»);
    - удаление ключей `data`/`binaryData` ConfigMap;
    - `spec.replicas` → 0;
    - удаление `spec.volumeClaimTemplates` или томов pod-шаблона.

    Опасный план — красная кнопка и фокус на «Назад к тексту».
12. **UI.**
    - Вкладка YAML: кнопка «Изменить» (`E` по `KeyboardEvent.code`). Редактор — тот же
      ленивый CodeMirror без `readOnly`.
    - Панель: «Просмотреть изменения» (`Ctrl+Enter`) и «Отмена». Живые обновления текст
      редактора не заменяют. Сменилась ревизия объекта — полоса «объект изменился на
      сервере».
    - Просмотр — модальный диалог:
      - где/что;
      - «ожидаемый результат (проверен сервером без записи)» или «рассчитан локально, без
        проверки сервером»;
      - предупреждения, права, разница;
      - кнопки «Применить» и «Назад к тексту».

      `conflict` при записи — в диалоге, с кнопкой «Посмотреть заново».
    - **Разница** — `web/src/edit/diff.ts`:
      - строки сводятся к номерам (хэш-таблица), сравнение O(1);
      - Myers с обрезкой общих концов и **бюджетом работы**; превышен — средний участок
        показан заменённым целиком с пометкой;
      - хранение `trace` — только используемые диагонали;
      - отображение порциями по 2 000 строк: «показать следующие N» доходит до конца, всё
        достижимо до подтверждения; строки длиннее 2 000 символов свёрнуты, «показать
        строку целиком» раскрывает её. Усечённая разница никогда не единственный способ
        увидеть изменения. Кроме того, заголовок называет общее число изменённых строк, а
        столкновения перечислены отдельно (решение 8).

      Считается один раз на просмотр, не на ввод. Тесты: полная замена 5k строк, 300k
      коротких строк, одна строка 3 МБ — всё в пределах 200 мс и без роста памяти сверх
      ограничений.
    - **Несохранённые правки не теряются молча.** Esc (вне панели поиска), закрытие деталей,
      переход по связям, смена вкладки, вида или target-а — подтверждение «Отбросить правки?».
      Фокус — «Продолжить правку».

## Спайк на kind (2026-09-30)

- Merge patch `--dry-run=server` с `metadata.uid` и верным `resourceVersion` возвращает
  результат (`null` удалил ключ); объект не изменён, версия в ответе прежняя.
- С устаревшим `resourceVersion` — 409 Conflict и в dry-run.
- С чужим UID — 422 `metadata.uid: field is immutable`, как в P4.

## Контракт

```go
// core
type EditDoc struct {
    Ref  Ref    // с UID прочитанного объекта
    Text string // показанный документ (решение 3)
    Base string // подписанная база (решение 10)
}
type EditPlan struct {
    Where       LiveTarget
    Before      string     // текущий объект (решение 3)
    After       string     // ожидаемый результат
    Checked     bool       // After — от dry-run сервера (иначе локальное наложение)
    Changed     bool
    Rebased     bool       // версия базы ≠ текущей
    Collisions  []string   // пути, перезаписывающие изменения после открытия
    Destructive bool
    Warnings    []Message
    Rights      Rights
    Unavailable *Message
    Token       string     // только если писать можно
}
type EditResult struct { Message string; Version string; Actual string }

// provider (поля токенов открыто; подпись — API)
type Editor interface {
    EditSource(ctx, ref core.Ref) (core.EditDoc, EditBase, error)
    PrepareEdit(ctx, EditRequest) (core.EditPlan, *EditGrant, error) // Ref, Base, Original, Edited
    RunEdit(ctx, EditRun) (core.EditResult, error)                   // + Grant, Original, Edited
}
```

API: `GetEditSource`, `PrepareEdit`, `RunEdit` — с сессией, `ConfigRev` и подписью токенов.
Оба транспорта и `web/src/api/client.ts`. Предел текста — 3 МБ (`bad_request` сверх).

## Ревью реализации Task 1

Закрытие плана не означает приёмки реализации. Ревью Codex реализации Task 1 (`12c48df`) —
1 × P1, 4 × P2, все приняты, исправлены с тестами, падающими на старом коде:
- P1 — доказательством локального APIService служил любой JSON 200 с `spec` (например,
  Deployment). Теперь нужен конверт `apiregistration.k8s.io/v1` `APIService` с именем
  `<v>.<g>` и `spec.group/version` той же группы-версии. Иной ответ ничего не доказывает и не
  запоминается.
- P2 — `!!float` шёл через float64 (`9007199254740993.0` → …992). Теперь десятичный литерал
  проверяется по синтаксису YAML 1.2 и уходит как написан, в форме JSON (`+1.5` → `1.5`,
  `.5` → `0.5`, `007.25` → `7.25`). Значение вне float64, inf и nan отвергаются. Нетегированное
  `1e400` yaml.v3 читает как строку.
- P2 — ошибки чтения Secret (`EditSource`, `PrepareEdit`) шли с текстом сервера; теперь через
  `secretSafe`. Ветка «getting credentials» стояла до разбора статуса: ответ сервера с этими
  словами становился unauthorized и показывал текст. Теперь локальный сбой учётных данных —
  только ошибка без статуса (до отправки). Исправлено также в `classify` и в `failedWrite`
  действий.
- P2 — откат на локальный просмотр принимал любой 400 со словами «does not support dry run»,
  в том числе отказ webhook-а. Теперь только точная форма API-сервера
  `admission webhook "<имя>" does not support dry run`.
- P2 — у `PrepareEdit` не было срока, и закрытие сессии его не прерывало. Теперь срок
  `prepareEditTimeout` (30 с) и отмена вместе с сессией. После закрытия сессии или истечения
  срока разрешение не выдаётся.

Перепроверка Codex (`0d1fd41`): все 5 закрыты. Новое P2 — локальное наложение показывало
десятичный литерал через float64 (`sigs.k8s.io/yaml` читает числа обратно через float64):
`9007199254740993.0` как `9.007199254740992e+15`, а PATCH нёс точный литерал. Для
kube-apiserver это и есть сохранённое значение (проверено dry-run на kind: …992), но при
локальном наложении бэкенд неизвестен (агрегированный сервер может хранить точно), поэтому
локальный результат показывает то, что отправляется: `exactDecimals` в `editView` (маркеры
вместо нецелых `json.Number`, литералы возвращаются в текст). Режим «проверено сервером»
показывает ответ сервера как есть.
