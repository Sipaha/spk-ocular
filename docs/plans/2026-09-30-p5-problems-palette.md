# P5 — Problems, палитра, клавиатура, полировка, soak

> Для агентов: задачи выполняются по порядку, шаги отмечаются `- [x]`; каждая задача —
> отдельные коммиты `area: summary`, `make check` зелёный перед коммитом; каждое исправление и
> каждая возможность начинаются с теста, который падает без них.

**Цель:** открыв context, пользователь одним видом **Problems** видит, что сломано в выбранной
области (namespace или все) — pods, workloads, узлы, недавние рестарты и повторяющиеся Warning
events — с честным покрытием («узлы не видны: нет права list nodes»). `Ctrl+K` открывает
палитру: переход к виду, context-у, namespace-у, объекту текущей таблицы или недавнему объекту,
команды в стиле k9s (`:po`, `:deploy web`, `:ns demo`, `:ctx prod`). Всё приложение проходится
с клавиатуры, в том числе в русской раскладке. Память не растёт за час работы под «шумящим»
кластером.

**Спецификация:** `docs/specs/2026-09-29-spk-ocular-design.md` — «Kubernetes MVP — функции»
(Problems, навигация), «Ключевые технические решения» п. 3–6 (health, время без опроса, история
рестартов, Problems — «проблемы в наблюдаемой области»), «Состояние (SQLite)» (недавние
переходы), «Критерии успеха» (без роста памяти за час, `scripts/pss.sh`).

## Глобальные ограничения

- Всё из P0–P4 (AGENTS.md «Правила»). `internal/core`, `internal/api`, общий UI не знают
  pod/deployment/namespace: Problems — вид провайдера с обычными строками, палитра — поверх
  `KindDescriptor`, `Target`, `ScopesView`, строк видов.
- Никаких фоновых опросов кластера: Problems — это watch-и тех же кэшей (аренды), время — только
  локальные дедлайны.
- UX важнее экономии памяти; считается только Private_Dirty.
- Тесты действий и нагрузки — только на kind `ocular-dev`.

## Что уже есть (обзор 2026-09-30)

- Health считает провайдер в `project(u, now) → (cells, Health, next)`; `next` — момент, когда
  правило времени поменяет вердикт; у каждого вида свой планировщик дедлайнов
  (`view_watch.go`: по UID-инкарнации, перечитывание стора, поколения таймеров, тесты на
  фейковых часах). Правила времени: Pending ≥ 5 мин, NotReady ≥ 2 мин, OOMKilled за 10 мин,
  адрес LoadBalancer/Ingress.
- Истории рестартов нет (колонка — сумма `restartCount`); Warning events — Warning-строки своего
  вида, к объекту не привязаны.
- Клавиатура: `/`, стрелки/Enter в списке target-ов и таблице, `L`, `S`, `Delete`,
  `Shift+F10`, Esc в панелях; единого реестра нет, навигация по видам — только мышью.
- SQLite: `ui_prefs`, `target_state` (4 КБ на значение).
- Замеры: `scripts/pss.sh`, `kind-load.sh` (статичные 5000 ConfigMap + 3000 Pending pods),
  `measure-kind.mjs` (один проход). «Шумящего» стенда и часового прогона нет.

## Решения P5 (агент, 2026-09-30)

### Problems

- **Вид провайдера.** Kubernetes отдаёт kind `problems` (группа — первая, заголовок
  «Problems»), scoped как pods. Строка — **проблема объекта**, не объект: `Row.ID` =
  `<kind>/<uid>` для health-проблем и `<kind>/<uid>/events/<reason>` для серии событий; `Row.Ref`
  указывает на сам объект (открыть детали, логи, терминал, действия — как у его вида: UI берёт
  возможности по `Ref.Kind`, не по виду таблицы). Колонки: Severity (status), Kind (вид объекта),
  Namespace, Name, Reason, Message, Since (age). Сортировка по умолчанию — severity, затем since.
- **Что проблема:** health объекта `error`, `warning`, `unknown` (узел Ready=Unknown).
  `progressing` и `terminating` — нет (rollout идёт, pod ждёт grace), кроме тех, что правила
  времени уже превратили в warning (Pending ≥ 5 мин, NotReady ≥ 2 мин, rollout deadline).
  Состояние считается **той же функцией** health, что и строка вида (один источник правды).
- **Детекторы = аренды обычных кэшей.** Вид Problems в области берёт аренды: pods, deployments,
  statefulsets, daemonsets, replicasets (только как владельцы — ReplicaSet сам не проблема, пока
  его Deployment здоров), jobs? — нет (нет kind-а, бэклог), nodes (кластерные: только при правах
  list/watch), events (Warning, в области). Аренды — те же ключи кэшей, что у таблиц: открытая
  таблица pods и Problems делят один informer. Выключение вида снимает аренды (60 с grace).
- **Покрытие честно.** `ViewStatus` получает `Notes []string` (provider-агностично: «что не
  видно»): «узлы: нет права list» / «events: кэш недоступен: …». Состояние вида — `ready`, пока
  хотя бы один детектор работает; все упали — `error` с классом. UI показывает notes под
  заголовком (не alert).
- **История рестартов (п. 5 спецификации).** В сессии — `restartLog`: по (pod UID, контейнер)
  база при первом наблюдении, положительные дельты с локальным временем в кольце (≤ 16 на
  контейнер), уменьшение счётчика/новый UID — новая база; разрыв наблюдения (кэш остановлен)
  помечается — «≥ N рестартов за 10 мин» говорится, только если наблюдение непрерывно, иначе
  «рестарты с HH:MM». Обновляется из обработчика pods-кэша (дешёво, без сети). Правило: ≥ 3
  рестарта за 10 мин → warning «RecentRestarts», дедлайн — когда самый старый выйдет из окна.
  Колонка Restarts таблицы pods не меняется; health pod-а получает issue — строка pods и
  Problems согласованы.
- **Warning events как свидетельство.** Серия (involvedObject UID + reason) с Warning-событием,
  `lastTimestamp`/`eventTime`/`series.lastObservedTime` за последние 15 мин → строка
  «<reason> ×count, последнее N назад» (dedup по серии; count — сумма). Истекает дедлайном.
  События без UID объекта — по kind/namespace/name.
- **Дедлайны Problems** — тот же планировщик `view_watch.go`, обобщённый на «строки из
  нескольких кэшей»: переоценка объекта по его ключу.
- **Счётчик в навигации:** пункт «Problems N» (N — строки вида, если он открыт; иначе без
  числа — фонового вида ради счётчика не держим).

### Палитра (`Ctrl+K`)

- Модальная палитра поверх рабочей области: поле + список (виртуальный, ≤ 200 показанных).
  Источники: виды текущего target-а, target-ы (все провайдеры), scopes (живой список
  namespaces), строки открытой таблицы (имя, namespace), недавние объекты текущего target-а.
- Fuzzy — свой небольшой скорер (подпоследовательность, бонусы за начало слова/точное
  совпадение/регистр; латиница и кириллица — раскладка не переводится). Без зависимостей.
- Команды k9s: `:<вид> [имя]` (алиасы из дескриптора: `KindDescriptor.Aliases` —
  `po`, `deploy`, `sts`, `ds`, `svc`, `ing`, `cm`, `sec`, `no`, `ns`, `ev`, `rs`, `problems`),
  `:ns <имя>|all`, `:ctx <имя>`. Алиасы — данные провайдера, UI их не знает.
- Недавние: таблица SQLite `recent_objects` (provider, target, kind, scope, name, uid, title,
  opened_at; ≤ 50 на target, вытеснение по времени) — запись при открытии деталей; API
  `RecentObjects`/`TouchRecent`. Исчезнувший объект открывается с «Этого объекта больше нет».

### Клавиатура

- Реестр горячих клавиш `web/src/shortcuts.ts`: одно место, `KeyboardEvent.code`, игнор в
  полях ввода/терминале/CodeMirror (кроме явно разрешённых: `Ctrl+K`, Esc), список для справки.
- Глобальные: `Ctrl+K` палитра, `?` справка (список из реестра), `F6`/`Shift+F6` — по кругу
  области: список target-ов → навигация видов → таблица → детали → нижняя панель.
- Навигация видов: стрелки/Home/End/Enter (roving tabindex). Таблица: + PageUp/PageDown,
  Home/End. Детали: Backspace/Alt+← — назад по связям; «хлебные крошки» в заголовке деталей
  (исходный объект › связанный › …) кликабельны.
- Фокус не теряется: закрытие деталей, диалогов, меню возвращает его туда, откуда открывали
  (P4 уже так для меню/диалога).

### Полировка (только найденное, без новых возможностей)

- Бэклог P4: единственное число вида в диалоге (`KindDescriptor.Singular`), тексты последствий
  на ключах + параметрах (ru/en). Бэклог P3: названия уровней «Pod/Container» в диалоге терминала
  от провайдера. Ответ действия после клиентского таймаута обновляет открытый диалог.
- Пустые/загрузочные состояния, заметные только при прогоне с клавиатуры, — по находкам
  desktop-прогона.

### Soak

- «Шумящий» кластер — **kind + `scripts/kind-churn.sh`** (не фейковый apiserver: реальные
  watch/relist/bookmark-и важнее): в `ocular-churn` каждые ~2 с создание/удаление pods,
  scale deployment-ов 1↔5, patch ConfigMap-ов, Warning events, crashloop-pod (рестарты), pod с
  потоком логов. `up`/`down`, параметры темпа.
- Прогон: desktop под Xvfb, открыты pods (все namespaces), Problems, детали с events, follow
  логов deployment-а, терминал, туннель; каждые 60 с — `pss.sh` + `/api/_test/stats` (в desktop
  — `--test-api`?) → CSV. Час. Критерий: наклон Private_Dirty за последние 30 мин ≈ 0 (< 1 МБ/10
  мин), счётчики видов/кэшей/потоков стабильны. Итог — в спецификацию (критерий успеха).
