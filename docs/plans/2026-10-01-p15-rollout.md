# P15 — Deployment: откат к ревизии, пауза и возобновление выкатки

> Для агентов: задачи выполняются по порядку, шаги отмечаются `- [x]`. Каждая задача — отдельные
> коммиты `area: summary`, `make check` зелёный перед коммитом (коммит — только по его коду
> выхода). Каждое исправление и каждая возможность начинаются с теста, который падает без них
> (проверка мутацией на старом коде).

**Цель:** у Deployment появляются действия **Откатить…** (`undo`: шаблон pod-ов становится
шаблоном выбранной прошлой ревизии — как `kubectl rollout undo --to-revision=N`, со списком
ревизий и тем, что изменится), **Приостановить выкатку** (`pause`) и **Возобновить выкатку**
(`resume`) — как `kubectl rollout pause/resume`. Сейчас после неудачного деплоя Ocular только
показывает беду, а чинить приходится kubectl-ом.

**Почему этот этап (выбор агента, 2026-10-01; пользователь просил не ждать его выбора):** самая
частая неприятность на живых кластерах после выкатки — «новая версия плохая»; откат с видимыми
ревизиями и разницей шаблонов — наибольшая ежедневная польза из бэклога. Английские тексты в
русском UI — полировка работающего; удаление namespace по имени и compose-файлы — реже/крупнее.

**Архитектура:** контракт действий P4 (`PrepareAction` → просмотр → один `RunAction`) и один
новый общий тип параметра — **выбор из вариантов** (`core.ParamChoice`): варианты приходят в
самом плане (`ActionPlan.Choices`), выбранное значение — в `ActionParams.Choice`, план для
выбранного значения просматривается заново (как `count` у scale). Без новых методов API. Агенты
(P14) получают действия и выбор тем же путём (`PrepareAction` с `params.choice`).

**Спецификация:** `docs/specs/2026-09-29-spk-ocular-design.md`; пункт — `docs/backlog.md`
(«Действия (из P4): … rollout undo/pause/resume»). Принципы: Read-first, destructive — с
подтверждением, все contexts RW без read-only-пометок.

## Глобальные ограничения

- Всё из P0–P14 (AGENTS.md «Правила»), особенно правила действий: `RunAction` читает строго по
  UID, `Expect` связывает всё, что прочитали эффекты плана, несовпадение — `conflict` без
  записи; каждая запись — один HTTP-запрос, неоднозначный ответ — `unknown` без повторов;
  повтор — только когда перечтение доказывает, что записи не было (≤ 3). Маршрут — в `Expect`.
- Никаких опросов: ход выкатки после отката/возобновления виден вживую в таблицах (Deployments,
  ReplicaSets, Pods).
- Все contexts RW. Тесты записи — только kind `ocular-dev`, в собственном namespace теста
  (удаляется); образы — только уже загруженные на узлы (`busybox:1.36`): ревизии различаются
  переменной окружения/командой, не образом из сети.
- Ручные запуски — изолированные HOME/DOCKER_CONFIG, цель по точному имени.

## Решения P15 (агент, 2026-10-01)

1. **Объём.** `apps/v1` Deployment: `undo`, `pause`, `resume` рядом с restart/scale/delete.
   StatefulSet/DaemonSet (история в ControllerRevision) — бэклог. «История ревизий» как
   отдельный раздел деталей — не делаем: список ревизий — в диалоге отката (там он нужен).
2. **Параметр «выбор» в `core`.** `ActionParam.Kind = "choice"` (`core.ParamChoice`);
   `ActionParams.Choice *string`; `ActionPlan.Choices []ActionChoice` —
   `{Value string, Title Message, Details []Message, At int64, Current bool,
   Unavailable *Message}`; `At` — unix ms, 0 — неизвестно (как `Cell.Time`/`Issue.Since`; в `core`
   нет `time.Time`). `CheckParams`: у действия без параметра `Choice` запрещён; у `choice` —
   `Count` запрещён, при Run выбор обязателен; значение сверяет провайдер (варианты живые).
   Почему общий тип, а не «ревизия»: `core` провайдер-агностичен; ревизия — один из выборов.
   Исключает: отдельный метод API «история».
   **Изменения — не список объектов** (ревью P2-1): новое `ActionPlan.Changes []Message` —
   что изменится в самом объекте (строки разницы). `Lists` остаются «объекты, которых касается
   план» с `Ref` (агентский `judge` отказывает по элементу без `Ref` — `listsOutside`,
   `agentapi/write.go:131`); строки разницы там сломали бы любой откат агента. `Changes` —
   целиком (как `Lists`: UI показывает порциями, первые 100 и «показать ещё N»); агенту — в
   `PlanView.Changes []string`.
3. **Ревизии.** ReplicaSet-ы, которыми владеет Deployment (controller UID — как `owned`),
   включая сведённые в 0, с аннотацией `deployment.kubernetes.io/revision`; по убыванию номера.
   **Значение варианта — имя RS** (ревью P3-2: номер ревизии переезжает при каждом откате, имя
   RS — нет и понятно агенту); заголовок «Ревизия N». Вариантов не больше 50 новейших (при
   `revisionHistoryLimit` по умолчанию 10 — почти всегда все); отброшенные — строкой
   предупреждения «ещё N старых ревизий не показаны» (выбор — не список объектов, контракт
   `Lists` «целиком» его не касается). Текущая — та, чей шаблон равен шаблону Deployment без
   метки `pod-template-hash` в метках шаблона (не селектора; как kubectl `EqualIgnoreHash`); её
   не выбрать (Unavailable «это текущий шаблон»). Детали варианта — `At` = создание RS,
   `kubernetes.io/change-cause` (если есть), образы контейнеров, «pod-ов: готово/всего». Нет прав
   на list ReplicaSets — план Unavailable с причиной.
4. **План отката.** Без выбора — только варианты (эффектов нет, Run недоступен). С выбором:
   эффекты — «шаблон pod-ов станет шаблоном ревизии N; она станет новой ревизией M» + выкатка
   по стратегии (слова restart: RollingUpdate с maxSurge/maxUnavailable или Recreate);
   `Changes` — плоская разница путей текущий → выбранный (`containers[app].image: a → b`,
   `…env[X]: добавлена/убрана/a → b`, прочее — «изменено»); `env` с `valueFrom` показывается
   ссылкой (`secretKeyRef x/key`), никогда не значением — разница читает только шаблоны (тест). Не destructive (как restart; число
   реплик не меняется). Unavailable: удаляется; **приостановлен — «сначала возобновите»** (как
   kubectl: откат приостановленного не выкатится); выбранный = текущий; выбранной ревизии нет
   среди вариантов (Prepare — Unavailable «ревизии больше нет»; Run — `conflict`).
5. **Запись отката — свой путь запуска** (ревью P2-3). Общий `RunAction` считает `Expect` по
   одному Deployment-у, а план отката зависит и от выбранного RS. Поэтому `undo` — отдельный
   `runUndo` (как `runNow`/`runDrain`), каждая попытка (≤ 3): читает Deployment по UID, заново
   перечисляет его RS, находит выбранный по имени (нет — `conflict` «ревизии больше нет»),
   считает `undoExpect(Deployment, RS)`; несовпадение — `conflict` без записи; тело строится
   **из прочитанного в этой попытке** (шаблон этого RS, аннотации этого Deployment-а), не из
   плана. `failedWrite` получает функцию пересчёта `Expect` (общий путь передаёт
   `actionExpect`, `runUndo` — перечтение Deployment + RS), остальная классификация общая.
   `undoExpect` — hash: действие, выбор, маршрут; у Deployment — UID, deleting, paused,
   `spec.template`, replicas, strategy (всё, что читают эффекты); у RS — UID, номер ревизии,
   hash шаблона без `pod-template-hash`.
   Тело — JSON Patch одним запросом: `test /metadata/uid`, **`replace /metadata/resourceVersion`
   прочитанным значением** (ревью P2-2), `replace /spec/template` (шаблон RS без
   `pod-template-hash` в метках шаблона) и аннотация `kubernetes.io/change-cause` — как у
   ревизии (есть — `add`, нет у ревизии, есть у Deployment — `remove`; путь `~1`-экранирован;
   нет `metadata.annotations` — `add` всего объекта). Прочие аннотации не трогаем (kubectl
   копирует все, кроме служебных, — сознательно уже).
   *Почему не `test /metadata/resourceVersion`* (проверено на kind 2026-10-01, `kubectl patch
   --type=json --dry-run=server`): неудачный `test` — голый 422 (`IsInvalid`), неотличимый от
   отказа валидации, и цикл его не повторяет — откат во время выкатки (статус меняет версию
   постоянно) отказывал бы. Устаревшая версия в `replace` — предусловие обновления: 409
   Conflict, который цикл повторяет после перечтения. Неудачный `test /metadata/uid` — тоже 422,
   но перечтение по UID даёт `gone` («заменён тем временем») — верно.
   Права — `patch deployments` и `list replicasets`.
6. **Пауза / возобновление.** JSON merge patch `spec.paused: true|false` с `metadata.uid` и
   `resourceVersion` (как suspend CronJob), общий путь `RunAction`. Unavailable: `pause` у
   приостановленного, `resume` у неприостановленного, удаляемый. Эффекты: pause — «изменения
   шаблона не выкатываются до возобновления; начатая выкатка останавливается как есть (старые и
   новые pod-ы остаются)»; resume — «выкатка продолжится; накопленные за паузу изменения
   шаблона (если есть) будут выкачены» + стратегия. Условное «если шаблон отличается от текущей ревизии» не
   делаем: оно зависит от списка RS, а `Expect` resume — только Deployment (ревью P2-3
   предлагало привязать RS; безусловная формулировка честна и не требует второго чтения).
   `Expect` — UID, deleting, paused, generation (покрывает весь spec, в том числе стратегию).
   «Приостановлен» в таблице уже есть: причина здоровья `Paused`
   (`kind_workloads.go:102`); агенты видят её в `RowView.Health` ListObjects (ревью P3-4) —
   тест agentapi это закрепляет.
7. **Подписи.** `act.undo` «Roll back…»/«Откатить…», `act.pause` «Pause rollout»/«Приостановить
   выкатку», `act.resume` у Deployment — существующий «Resume»/«Возобновить» (id общий с
   CronJob; эффекты — по виду). Все тексты — ключи сообщений провайдера (`kubernetes.undo.*`,
   `pause.*`, `resume.*`, `done.*`, `unavailable.*`) с русскими переводами; тест «у каждого
   действия есть done-текст» расширяется.
8. **UI.** `ActionDialog`: параметр `choice` — список вариантов (радиокнопки, новейшие сверху,
   текущий помечен и недоступен, детали мелко); выбор пересобирает план (как смена count —
   «Выполнить» только после просмотра плана для этого выбора); клавиатура — стрелки по
   вариантам; `Changes` — блок «Изменения шаблона» порциями. Меню строки/деталей — из
   дескрипторов (суффикс «…» уже есть для параметров).
9. **Агенты (P14).** Новые глаголы `action:undo|pause|resume` появляются сами; `PrepareAction`
   без `choice` отдаёт варианты (`PlanView.Choices`), с `choice` — план с `Changes`; описание
   `params` в схеме каталога говорит про `choice`. Тесты agentapi: план отката с `Changes`
   проходит `judge`; выбор проходит, неизвестный — отказ провайдера; Deployment на паузе — в
   строках `Health.Reason = "Paused"`. Редактор грантов (ревью P3-5): при выданном
   `action:undo` — предупреждение `agents.warn.undo` «Откат ставит любой прошлый шаблон pod-ов:
   старые образы, команды, тома, ServiceAccount» (как предупреждения о правке, P14).
10. **Синтетика и тесты.** Синтетические Workloads: `undo` с тремя ревизиями (для e2e диалога) и
    `pause`/`resume`. Unit (fake dynamic client): список ревизий и текущая, разница путей,
    тело JSON Patch (из объекта этой попытки), Unavailable, `conflict` при смене шаблона /
    исчезновении или замене RS между Prepare и Run, **повтор при сдвинутой версии и прежнем
    Expect (409 от `replace resourceVersion`)**, 422 от `test uid` → «заменён», pause/resume.
    kind: настоящий откат (ревизии по env), номер ревизии растёт, pause → изменение шаблона не
    создаёт RS → resume создаёт; откат во время идущей выкатки проходит. e2e: синтетика (диалог
    выбора), kind (откат из UI).
