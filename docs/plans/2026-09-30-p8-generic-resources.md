# P8 — Kubernetes: все ресурсы API (CRD и не описанные виды)

> Для агентов: задачи выполняются по порядку, шаги отмечаются `- [x]`; каждая задача —
> отдельные коммиты `area: summary`, `make check` зелёный перед коммитом; каждое исправление и
> каждая возможность начинаются с теста, который падает без них.

**Цель:** в открытом kube context-е пользователь видит **все** ресурсы API, которые можно
list+watch, а не только 11 описанных видов: Custom Resources (cert-manager, Argo, свои CRD
SPK…) и встроенные виды без своей проекции (Jobs, CronJobs, PVC, PV, StorageClasses,
ServiceAccounts, Roles, HPA…). Колонки — **те же, что у `kubectl get`** (server-side Table:
`additionalPrinterColumns` у CRD, встроенные принтеры у остальных), живое обновление,
детали (факты, YAML, связи, события), удаление с тем же планом и подтверждением, палитра
(`:certificates`, короткие имена). Описанные виды P1 не меняются.

**Спецификация:** `docs/specs/2026-09-29-spk-ocular-design.md` — «Provider API» (виды
квалифицированы группой: `"apps/deployments"`, чтобы CRD разных групп не сталкивались; GVR
внутри адаптера), «Ключевые технические решения» (watch через общий кэш, никаких фоновых
опросов, действия: план → подтверждение → запуск по UID). Бэклог: «CRD-виды (generic-колонки,
`additionalPrinterColumns`)».

## Глобальные ограничения

- Всё из P0–P7 (AGENTS.md «Правила»). В `internal/core`, `internal/api` и общем UI не
  появляется Kubernetes-знание (discovery, Table, CRD) — только новые общие поля/события.
- Никаких фоновых опросов: набор ресурсов обновляется по событию (watch CRD, если разрешён)
  или явно (`F5` в навигации / переоткрытие target-а), не по таймеру.
- Права пользователя не предполагаются: discovery разрешён всем аутентифицированным
  (`system:discovery`), чтение CRD-объектов и list ресурса — нет; отказ показывается, а не
  прячет вид молча.
- Тестовые записи — только kind `ocular-dev`; кластеры пользователя не трогаются.
- UX важнее экономии памяти; считается только Private_Dirty (критерий soak — спецификация).

## Что уже есть (обзор 2026-09-30, карта — отчёт исследования)

- Вид: `core.KindDescriptor` (`internal/core/kind.go:46-87`: ID, Title, Singular, Group,
  Columns, Scoped, Aliases, Actions, EventsKind, Sort, NotCovered…); внутри провайдера
  `kindDef{desc, gvr, namespaced, keep, pre, project, virtual}` (`kinds.go:13-30`). Реестр —
  **глобальный фиксированный** `allKinds` (`session.go:31-37`), алиасы/единственное число/
  действия — отдельные карты по `*kindDef` (`session.go:40,57`, `actions.go:45`), слияние в
  `descriptors()` (`kinds.go:130-144`).
- API: `ListKinds` (`api.go:27`) → `sess.Kinds()`; `OpenView` отвергает неизвестный вид
  (`sessions.go:189-196`). UI: `Workspace.tsx:112` — `listKinds` **один раз** на target,
  группы навигации — по `k.group` в порядке бэкенда.
- Кэш (`cache.go`): ключ `{gvr, namespace, selector}`, `dynamic.Interface` + unstructured
  informer, transform по `keep`/`pre` — **универсален по GVR**. Проекция —
  `func(u, now) ([]core.Cell, core.Health, time.Time)`, ячейки по позиции колонок.
- Детали: `Get` (dynamic, UID, YAML без managedFields/last-applied) и факты из ячеек —
  универсальны; связи вверх по ownerReferences — универсальны, но `kindFor`/`kindOf`
  (`resource.go:152-194`) — switch по встроенным: владелец-CR виден, но не открывается.
  События объекта — `EventsKind="events"` по `involvedObject.uid` для всех.
- Delete (`actions.go:240-243`) — по `def.gvr` с предусловиями UID/resourceVersion,
  последствия (`actions_effects.go`) — частные случаи StatefulSet/ReplicaSet/Pod, иначе
  `delete.requested`; права — SSAR по `def.gvr`. Restart/scale — только workload-ы.
- Discovery и чтение CRD в коде **нет**. Problems: `NotCovered` называет «custom resources».
- Палитра: алиасы от провайдера (`kindAliases`), UI сопоставляет id, последний сегмент id,
  title и алиасы (`web/src/palette/items.ts`).

## Решения P8 (пересмотрены по ревью плана Codex и спайку)

### 1. Набор ресурсов — discovery, асинхронно и без потерь при сбоях

- На сессию — **каталог видов**: статические виды P1 (всегда, сразу) + обнаруженные.
  Обнаружение — **свой разбор aggregated discovery v2** (`/api` и `/apis`, два запроса) с
  запасным путём v1 (`/api`, `/apis`, затем по группе-версии — ограниченная параллельность,
  общий дедлайн и лимит размера ответа). Без discovery-клиента client-go (тянет
  openapi/gnostic). Предпочтительная версия — **по GroupResource**: первая обслуживаемая
  версия группы, в которой ресурс есть (ресурс, которого нет в первой версии, берётся из
  следующей). Берутся ресурсы с `list` **и** `watch`, не subresource-ы, не покрытые
  статическими видами (по группе+ресурсу), не `events` (оба API — статический вид).
  Глаголы discovery — не права: права остаются «неизвестно» до SSAR / ответа сервера.
- **Никакого I/O в `Provider.Open` и синхронном `Kinds()`** (Open идёт под `Service.sessMu`):
  discovery — фоновая single-flight задача сессии (последнее поколение выигрывает, общий
  дедлайн, отмена и ожидание на `Close`). `Kinds()` отдаёт текущий снимок каталога; до
  первого ответа — статические виды и статус каталога «обнаружение…».
- **Сбой — не доказательство исчезновения**: группы, не ответившие при повторном discovery
  (таймаут, 503 aggregated API, частичный отказ корня, а также версия с `freshness: Stale` в
  ответе 200 — её ресурсы и более поздние версии группы не используются), сохраняют последние известные виды с
  пометкой «не подтверждено: <группы>»; вид удаляется только по **успешному** ответу,
  в котором его нет. Сбой не переключает ресурс на непредпочтительную версию. Первый
  discovery со сбоем — статические виды + заметка.
- **Обновление каталога** — по событию, не по таймеру: informer CRD (если разрешён
  list+watch `customresourcedefinitions`; keep — имя, группа, версии, scope, printer
  columns-отпечаток) как триггер повтора с дебаунсом 1 с; иначе — `F5` в навигации,
  переоткрытие target-а, resync хаба (решение 5).
- Kind ID обнаруженного: `<group>/<plural>` (core — `<plural>`), Title — из `responseKind.kind`
  во множественном (как `plural`), Singular — `singularResource` (или Kind), Aliases —
  `shortNames` + singular + plural, Scoped — `scope == Namespaced`.

### 2. Колонки и строки — server-side Table под informer-ом

- Ресурс обнаруженного вида читается с `Accept: application/json;as=Table;v=v1;
  g=meta.k8s.io` и `includeObject=Object`: сервер считает колонки (встроенные принтеры,
  `additionalPrinterColumns`) — без прав на чтение CRD и без хранения больших spec ради
  JSONPath. JSONPath CRD — возможное обогащение позже, не основной путь.
- **Адаптер ниже Reflector-а** (сырой Table до Reflector-а не доходит — он его отвергает):
  - `ListFunc`: Table → список объектов **с GVK ресурса** (обрезанный объект строки + ячейки
    во внутреннем поле), `resourceVersion`, `continue`, `remainingItemCount` сохраняются
    (пагинация не обрезает коллекцию).
  - `WatchFunc`: события Table → объекты с GVK ресурса; `BOOKMARK` — объект ресурса с RV и
    **аннотациями как есть** (`k8s.io/initial-events-end`), до transform-а кэша; `ERROR`
    (Status) — как есть (410 — relist, не исчезновение вида); заголовки колонок —
    **на поток**: первое событие несёт `columnDefinitions`, последующие — нет.
  - WatchList (`sendInitialEvents`) для Table-вида **не объявляется**: Reflector идёт путём
    List + Watch (тест: адаптер не получает WatchList-опций; пустой и непустой список).
  - Ответ не Table (406, старый сервер, aggregated API без Table) → тот же вид в обычном
    формате (list/get/watch) с колонками Name/Namespace/Age; **401/403 — не запасной путь**,
    а отказ, как сейчас.
- **Колонки** — `columnDefinitions` с `priority == 0`; wide (`priority > 0`) — в фактах
  деталей. Типы ячеек: `integer`/`number` — число (`num`), `boolean` — текст `true`/`false`,
  `null`/нет значения — пусто (не 0 и не false), прочее — текст сервера **как есть**.
  **Возраст** — живой `age` из `metadata.creationTimestamp` только при **известном
  происхождении** колонки: **точный встроенный GroupResource** kube-apiserver из
  статического списка (`batch/jobs`, `persistentvolumeclaims`, `rbac.authorization.k8s.io/roles`…)
  с колонкой «Age» его принтера — не любая группа встроенного имени: CRD может обслуживать
  `foos.networking.k8s.io` (защищённые группы требуют лишь аннотации одобрения API), и не по
  суффиксу `*.k8s.io` (`gateway.networking.k8s.io`, `snapshot.storage.k8s.io` — CRD); или
  колонка CRD, прочитанной informer-ом CRD, с JSONPath `.metadata.creationTimestamp` в той
  версии, что обслуживает вид. `description` колонки — не
  доказательство (сервер берёт его у автора CRD как есть). Прочие даты — текст сервера на
  момент последнего изменения строки (сервер отдаёт длительность, метку не восстановить);
  периодических перечитываний ради них нет.
- **Схема вида — эпоха**: неизменяемый снимок {GVR, scope, режим (Table/обычный формат),
  колонки: порядок, исходные индексы, имя, тип, priority, признак возраста} с номером.
  `OpenView` обнаруженного вида, пока схемы нет, делает один `limit=1` Table-запрос (с той же
  областью и селекторами, что у вида, — не шире по RBAC) и закрепляет эпоху 1 (не заглушку;
  этот ответ не наполняет кэш и не заменяет его RV). Кэш — ключ `{GVR, scope, selector,
  эпоха}`. Схема сверяется **на каждом ответе Table**: пробный запрос, каждая страница
  list-а и relist, заголовки watch, `Get` для фактов. Отличие → страница не применяется, новая
  эпоха: кэши старой выводятся из обращения (их поздние события отбрасываются), виды
  получают «схема изменилась» и открываются заново; метаданные вида и строки — одной эпохи.
  Смена отпечатка printer columns у прочитанной CRD и `F5`/resync (без прав на CRD)
  **перепроверяют** схемы открытых видов, даже если discovery не изменился. Проба схемы —
  single-flight на вид+маршрут, с дедлайном и отменой; поздний ответ старой пробы не
  затирает более новую эпоху. Режим (Table/обычный) закрепляется за маршрутом и эпохой:
  406 на watch при успешном Table list не переключает вид туда-обратно; 410/500 и ответ-Status
  — не признак «формат не поддержан».
- Health строки (обрезанный объект хранит `metadata.generation`, `deletionTimestamp`,
  `status.conditions` с `observedGeneration`): `deletionTimestamp` → terminating; condition с
  **явным** `observedGeneration` < `generation` — устарела, не утверждает ни ok, ни ошибку
  (health — progressing «ожидает контроллер»); без `observedGeneration` — считается текущей.
  Порядок: `Failed`/`Degraded` True → error; `Ready` (иначе `Available`) False → error,
  Unknown → progressing, True → ok; `Stalled` True → warning (поверх ok); иначе нейтрально.
  Не зависит от порядка условий в массиве.

### 3. Операции закрепляют снимок вида; детали, связи, delete

- Вид, `Get`, план и запуск действия получают **снимок маршрута** (GVR, scope, эпоха схемы)
  один раз и используют только его — повторного поиска по каталогу посреди операции нет.
  `Expect` действия включает маршрут (GVR + scope); `RunAction` сверяет его с текущим
  каталогом **до первой записи**: изменился → `conflict` («ресурс API изменился — откройте
  план заново»), подтверждённый план не перенаправляется молча. UID/RV-предусловия остаются.
- Факты — ячейки строки + wide-колонки свежего Table `Get` одного объекта.
- `kindFor`/`kindOf` — по каталогу сессии (apiVersion+Kind → вид): владелец-CR открывается.
- Delete — у вида с глаголом `delete`: последствия `delete.requested` + **финализаторы**
  («удаление ждёт финализаторы: …»); отсортированный набор финализаторов входит в `Expect`
  (иначе смена финализаторов между просмотром и запуском прошла бы незамеченной). Права —
  SSAR по GVR (неизвестно — остаётся неизвестно). Scale по `subresources.scale` — бэклог.
- Problems не расширяется (обнаруженные виды — в `NotCovered`).

### 4. Навигация

- Статические разделы не меняются. Обнаруженные виды — раздел «API-группы» (нейтрально:
  discovery не говорит, CRD это или aggregated API), подгруппы по API-группе, **свёрнуты по
  умолчанию**, раскрытие — в `target_state`; подгруппа с одним видом — без уровня; счётчик
  видов у заголовка; заметки «обнаружение…» / «не подтверждено: …». Палитра находит любой вид
  по имени/короткому имени без раскрытия.
- Общие поля `KindDescriptor.Subgroup` (подпись) и порядок от провайдера; UI не знает об
  API-группах.

### 5. Каталог в открытом UI: ревизия, доставка, окончательное удаление

- Каталог несёт **ревизию** (монотонную в пределах сессии) и идентичность target/сессии.
  Событие хаба «каталог изменился (ревизия N)» — подсказка: UI перечитывает `ListKinds`
  (ответы — «последний выигрывает», чужой target/сессия — отбрасываются); **то же
  перечитывание** — при resync/переподключении хаба и по `F5` (событие может потеряться).
- **Окончательное удаление вида** — отдельный общий статус вида/ошибки `removed` (не `gone`):
  `gone` по-прежнему значит «вид истёк — открыть заново» (замена сессии, истёкший вид), а
  `removed` — «ресурс больше не обслуживается API», вид **не** переоткрывается; UI понимает
  его и в событии `view_changed`, и в ошибке запроса. Смена эпохи схемы — третий случай:
  переоткрыть с новыми колонками.

## Спайк (Task 0, kind v1.37.0, 2026-09-30)

- **Discovery**: aggregated v2 (`Accept: application/json;g=apidiscovery.k8s.io;v=v2;
  as=APIGroupDiscoveryList`) — `/api` и `/apis`, два запроса, ~5 мс на kind; в ответе на
  ресурс: `resource`, `responseKind`, `scope`, `shortNames`, `singularResource`, `verbs`,
  `categories`, `subresources` (с глаголами — `scale` виден). Версии группы — в порядке
  предпочтения (первая — preferred). Discovery-клиент client-go тянет новые зависимости
  (openapi/gnostic) — не нужен: свой разбор v2 (+ запасной путь v1 для старых серверов).
- **Table list** (`as=Table;v=v1;g=meta.k8s.io`, `includeObject=Object`): `kind: Table`,
  `metadata.resourceVersion`, `columnDefinitions` (name/type/format/priority), строки с
  `cells` и полным объектом. CRD: колонки из `additionalPrinterColumns`, `priority: 1` — в
  определениях (wide). Встроенные: Jobs — Status/Completions/Duration/Age (все `string`),
  PVC — Status/Volume/Capacity/Access Modes/StorageClass/VolumeAttributesClass/Age.
- **Даты — не метки времени**: ячейка `date` у CRD — уже человекочитаемая длительность
  («40s»), у встроенных «Age» — `string` «5m». Живой возраст из ячейки не получить.
- **Table watch**: события — `Table` из одной строки (`MODIFIED` и т. д.), с объектом строки;
  `columnDefinitions` сервер шлёт только в первом событии потока (Codex: `NoHeaders` после
  первого) — колонки запоминаются на поток/эпоху.
- **BOOKMARK и ошибки в Table-watch** (второй спайк): BOOKMARK — `Table` с
  `columnDefinitions: null` и одной строкой, чьи ячейки пусты, а `object` — объект ресурса
  (`apiVersion`/`kind` ресурса, в `metadata` только `resourceVersion` и аннотации); первый
  же обычный event потока несёт `columnDefinitions`. Устаревший `resourceVersion` у watch —
  HTTP 200 и событие `ERROR` со `Status` 410 (`Expired`); у list с `resourceVersionMatch=Exact`
  — HTTP 410. `Get` одного объекта с Table-`Accept` — `Table` из одной строки с колонками.
- **Признак возраста**: `description` колонки «Age» у встроенных (Jobs, Pods) и у CRD без
  колонок — описание `creationTimestamp` из `ObjectMeta` («CreationTimestamp is a timestamp
  representing…»); у колонки CRD без своего описания — «Custom resource definition column (in
  JSONPath format): <путь>» (виден путь, у `Since` — `.metadata.creationTimestamp`).

## Фокус ревью (что тесты задач могут не поймать)

1. Набор видов меняется, пока вид открыт или его запрос в полёте: нет гонки между старым и
   новым реестром (вид не открывается по устаревшему GVR, `gone` — а не ошибка).
2. Watch в формате Table после 410/обрыва: relist не теряет и не дублирует строки, колонки
   не «съезжают» при смене версии CRD.
3. Кластер с сотнями CRD: discovery не блокирует открытие target-а (статические виды
   доступны сразу), навигация не тормозит, память — в запасе.
4. Права: discovery есть, list ресурса запрещён — вид показывает отказ; list CRD запрещён —
   набор всё равно собирается, обновление — по `F5`.
