# P10 — значения Secret: показать, скопировать, изменить

> Для агентов: задачи выполняются по порядку, шаги отмечаются `- [x]`. Каждая задача — отдельные
> коммиты `area: summary`, `make check` зелёный перед коммитом. Каждое исправление и каждая
> возможность начинаются с теста, который падает без них.

**Цель:** в деталях Secret пользователь видит его ключи с размерами и по явному действию
**показывает** значение одного ключа, **копирует** его в буфер обмена или **меняет** (в том
числе добавляет и удаляет ключ) — как «Show»/«Edit» секрета в Lens или
`kubectl get secret -o jsonpath | base64 -d` и `kubectl edit`. Сейчас значения видны только
маской `<N bytes>` (P1), а редактор YAML (P9) правит у Secret только `metadata`.

Значение никогда не показывается само: только по действию над одним ключом, только пока
открыты эти детали этого объекта, и нигде не остаётся — ни в кэшах, ни в SQLite, ни в логах,
ни в событиях, ни в сообщениях об ошибках.

**Архитектура:** provider-агностичная возможность сессии `ValueHolder` (объекты вида хранят
защищённые значения по ключам): `Values` (ключи и размеры), `RevealValue` (значение одного
ключа), `PrepareValueEdit`/`RunValueEdit` (правка ключа с просмотром и одной записью — тот же
протокол подписанных базы и гранта, что у P9). В общем UI нет слова Secret: вид объявляет
`KindDescriptor.Values`, секция деталей «Значения» строится по ответу `Values`.

**Спецификация:** `docs/specs/2026-09-29-spk-ocular-design.md`; пункт — из `docs/backlog.md`
(«Раскрытие значения Secret по явному действию», «правка значений Secret» после P9).
Принципы: Read-first, destructive — с подтверждением, все contexts RW без read-only-пометок.

## Глобальные ограничения

- Всё из P0–P9 (AGENTS.md «Правила»). Общий UI и `internal/core` не знают Kubernetes.
- **Значение уходит из Go только в ответе `RevealValue`** — одного ключа, одному запросу.
  Нигде больше: не в `Resource.yaml`/фактах/строках вида (как сейчас, маска), не в
  `PrepareValueEdit`/`RunValueEdit`-ответах (там только размеры), не в токенах (только хэш),
  не в логах Go (ни slog, ни klog), не в событиях, не в SQLite, не в сообщениях об ошибках
  (`secretSafe`, как в P9).
- Значения не кэшируются: `RevealValue` читает объект заново (GET по имени, сверка UID), берёт
  один ключ, остальное отбрасывает. Списочные кэши по-прежнему держат только имена ключей.
- Все contexts RW. Правка значения — только через просмотр и подтверждение; запись — один
  HTTP-запрос с uid + resourceVersion просмотра, без повторов (как P4/P9).
- Никаких опросов. Изменение объекта — по ревизии деталей (`useObjectRevision`).
- Тесты записи — только kind `ocular-dev`.

## Решения P10 (агент, 2026-09-30)

1. **Объём.** Для Kubernetes Secret (`data` и `stringData` при чтении — сервер отдаёт только
   `data`): список ключей с размерами; показать; копировать; изменить значение ключа; добавить
   ключ; удалить ключ. В бэклог: ConfigMap (значения и так видны в YAML), `binaryData`
   ConfigMap, загрузка значения из файла и сохранение в файл, просмотр сертификата
   (`kubernetes.io/tls`) в разобранном виде, Compose (секреты Compose — файлы).
2. **Контракт.** `KindDescriptor.Values bool`. Возможность сессии:
   - `Values(ref) → ValueList{ref (с UID), version, keys: [{key, size, text}]}` — `text`:
     значение — корректный UTF-8 без управляющих символов, кроме `\n`, `\r`, `\t`;
   - `RevealValue(ref, key) → Value{key, size, text, value}` — `value`: сам текст, если
     `text`, иначе base64 байтов; предел — 1 МБ (Secret целиком ≤ 1 МБ по etcd);
   - `PrepareValueEdit(req) → ValuePlan`, `RunValueEdit(run) → ValueResult` (решения 6–8).

   `Values` отдельно от `GetResource`, чтобы ключи обновлялись вместе с ревизией и не
   смешивались с общими фактами.
3. **Показ.** Кнопка «Показать» у ключа: значение появляется в строке ключа (моноширинно,
   перенос; > 64 КБ — первые 64 КБ и «показать целиком»), рядом «Скрыть» и «Копировать».
   Небинарное — как текст; бинарное — base64 с пометкой «двоичное, N байт».
   Значение живёт только в состоянии секции деталей и **скрывается** при:
   - закрытии деталей, переходе к другому объекту, смене вкладки, вида или target-а;
   - смене ревизии объекта (показанное могло устареть): ключ скрыт, строка говорит
     «значение изменилось — показать снова»;
   - «Скрыть все».

   Показ и копирование — без подтверждения (это чтение, как в Lens), но только по явному
   действию над одним ключом; «показать все» нет.
4. **Копирование.** «Копировать» читает значение заново (`RevealValue`) и кладёт в буфер
   (desktop — Wails `Clipboard.SetText`, browser — `navigator.clipboard`), не показывая его;
   уведомление «значение ключа K скопировано» — без значения. Бинарное копируется как base64
   (сказано в уведомлении). Буфер обмена не очищается автоматически (это системный буфер
   пользователя; сказано в справке).
5. **Где значение может утечь — и как нет.**
   - HTTP-транспорт browser-режима не логирует тела; `RevealValue` — обычный POST с
     bearer-токеном на loopback (как все методы).
   - Ошибки `RevealValue`/`Values` — через `secretSafe` (строки сервера о Secret не
     показываются).
   - UI не пишет значение в `localStorage`, `target_state`, недавние объекты, палитру,
     `title`-атрибуты и `aria-label`.
   - Go: значение — локальная переменная обработчика; объект после выбора ключа не
     удерживается.
   - Тест-ловушка: уникальная строка-маркер в Secret не встречается ни в одном ответе API,
     кроме `RevealValue`, ни в логе приложения, ни в SSE-событиях (e2e-kind и Go).
6. **Правка ключа — диалог «Изменить значение».** Поля: ключ (для нового — ввод имени,
   проверка `[-._a-zA-Z0-9]+`, ≤ 253), значение — многострочное поле, режим «текст» или
   «base64» (для бинарных — только base64; ввод проверяется). Исходное значение подставляется
   только если оно было показано. «Удалить ключ» — отдельная кнопка у ключа (тот же
   просмотр). Патч — `{"data": {K: base64(new)}}` или `{"data": {K: null}}`, с
   `metadata.uid` и `resourceVersion`.
7. **Просмотр правки (`PrepareValueEdit`)** — как P9, но без текстов значений:
   - где (context, сервер, namespace, вид, имя), ключ, «N → M байт» / «новый ключ, M байт» /
     «ключ удаляется»;
   - dry-run (Secret — описанный вид: маршрут доказан, решение 7 P9), отказ — `secretSafe`;
   - `immutable: true` — недоступно до запроса («Secret неизменяемый: создайте новый»);
   - последствия: pod-ы, использующие Secret как переменные окружения, не увидят изменения
     до перезапуска; смонтированные тома обновятся с задержкой kubelet-а (кроме `subPath`);
     список pod-ов — по ссылкам в `spec` pod-ов namespace-а (env/envFrom/volumes/
     imagePullSecrets), ограниченно, как связи P1; удаление ключа, который ссылается pod
     (`secretKeyRef` без `optional`), — опасно;
   - Secret с `type` `kubernetes.io/tls`/`dockerconfigjson`/`service-account-token` —
     предупреждение о формате, проверку делает сервер;
   - права — SSAR `patch secrets`;
   - изменилась ли версия с момента показа списка ключей (`rebased`), и если изменилось
     значение того же ключа — столкновение, план опасный.
8. **Токены** — как P9 (решение 10): база `Values` связывает маршрут, UID, версию; грант —
   маршрут, UID, текущую версию просмотра, **хэш** нового значения и ключ, режим. `RunValueEdit`
   заново строит патч из запроса, сверяет хэш и пишет один раз с предусловиями. Значение
   запроса не попадает ни в токен, ни в ответ.
9. **Защита несохранённого.** Открытый диалог с изменённым значением участвует в `guard.ts`
   P9 (закрытие деталей, переходы — «Отбросить правки?»).
10. **Права и отказы.** Нет `get secrets` — детали и так не открываются (`forbidden`); нет
    `patch` — просмотр «прав нет», без гранта. `RevealValue` у удалённого/заменённого объекта —
    `gone`.

## Контракт

- `internal/core/values.go`: `ValueKey{Key, Size, Text}`, `ValueList{Ref, Version, Keys,
  Base}`, `Value{Key, Size, Text, Value}`, `ValuePlan{Where, Key, Before, After (размеры, -1 —
  нет), Checked, Changed, Rebased, Collision, Destructive, Warnings, Rights, Unavailable,
  Token}`, `ValueResult{Message, Version}`.
- `internal/provider/values.go`: `ValueHolder` с `Values`, `RevealValue`, `PrepareValueEdit`,
  `RunValueEdit`; `ValueBase`, `ValueGrant` — открытые поля, подпись в API.
- `internal/api/values.go`: методы, подпись (HMAC `revKey`), маршруты HTTP и Wails
  (`routes_test.go` проверит).
- `web/src/api`: типы и клиент; `web/src/values/` — секция деталей и диалог.
