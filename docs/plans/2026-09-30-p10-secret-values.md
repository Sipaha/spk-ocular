# P10 — значения Secret: показать, скопировать, изменить

> Для агентов: задачи выполняются по порядку, шаги отмечаются `- [x]`. Каждая задача — отдельные
> коммиты `area: summary`, `make check` зелёный перед коммитом. Каждое исправление и каждая
> возможность начинаются с теста, который падает без них.

**Цель:** в деталях Secret пользователь видит его ключи с размерами и по явному действию
**показывает** значение одного ключа, **копирует** его в буфер обмена или **меняет** (в том
числе добавляет и удаляет ключ) — как «Show»/«Edit» секрета в Lens или
`kubectl get secret -o jsonpath | base64 -d` и `kubectl edit`. Сейчас значения видны только
маской `<N bytes>` (P1), а редактор YAML (P9) правит у Secret только `metadata`.

Значение никогда не показывается само: только по действию над одним ключом, только пока
открыты эти детали этого объекта, и нигде не остаётся — ни в кэшах, ни в SQLite, ни в логах,
ни в событиях, ни в сообщениях об ошибках.

**Архитектура:** provider-агностичная возможность сессии `ValueHolder` (объекты вида хранят
защищённые значения по ключам): `Values` (ключи и размеры), `RevealValue` (значение одного
ключа), `PrepareValueEdit`/`RunValueEdit` (правка ключа с просмотром и одной записью — тот же
протокол подписанных базы и гранта, что у P9). В общем UI нет слова Secret: вид объявляет
`KindDescriptor.Values`, секция деталей «Значения» строится по ответу `Values`.

**Спецификация:** `docs/specs/2026-09-29-spk-ocular-design.md`; пункт — из `docs/backlog.md`
(«Раскрытие значения Secret по явному действию», «правка значений Secret» после P9).
Принципы: Read-first, destructive — с подтверждением, все contexts RW без read-only-пометок.

## Глобальные ограничения

- Всё из P0–P9 (AGENTS.md «Правила»). Общий UI и `internal/core` не знают Kubernetes.
- **Значение уходит из Go только в ответе `RevealValue`** — одного ключа, одному запросу.
  Нигде больше: не в `Resource.yaml`/фактах/строках вида (как сейчас, маска), не в
  `PrepareValueEdit`/`RunValueEdit`-ответах (там только размеры), не в токенах (только хэш),
  не в логах Go (ни slog, ни klog), не в событиях, не в SQLite, не в сообщениях об ошибках
  (`secretSafe`, как в P9).
- Значения не кэшируются: `RevealValue` читает объект заново (GET по имени, сверка UID), берёт
  один ключ, остальное отбрасывает. Списочные кэши по-прежнему держат только имена ключей.
- Все contexts RW. Правка значения — только через просмотр и подтверждение; запись — один
  HTTP-запрос с uid + resourceVersion просмотра, без повторов (как P4/P9).
- Никаких опросов. Изменение объекта — по ревизии деталей (`useObjectRevision`).
- Тесты записи — только kind `ocular-dev`.

## Решения P10 (агент, 2026-09-30; ревизии 2 и 3 по ревью плана Codex)

1. **Объём.** Для Kubernetes Secret (`data` и `stringData` при чтении — сервер отдаёт только
   `data`): список ключей с размерами; показать; копировать; изменить значение ключа; добавить
   ключ; удалить ключ. В бэклог: ConfigMap (значения и так видны в YAML), `binaryData`
   ConfigMap, загрузка значения из файла и сохранение в файл, просмотр сертификата
   (`kubernetes.io/tls`) в разобранном виде, Compose (секреты Compose — файлы).
2. **Контракт.** `KindDescriptor.Values bool`. Возможность сессии:
   - `Values(ref) → ValueList{ref (с UID), version, keys: [{key, size, text}], base}` —
     `text`: значение — корректный UTF-8 без управляющих символов, кроме `\n` и `\t` (`\r`
     — не текст: поле ввода браузера меняет CRLF на LF, решение 6); `base` — подписанная
     база (решение 8);
   - `RevealValue(ref, key) → Value{key, size, text, value, uid, version}` — `value`: сам
     текст, если `text`, иначе base64 байтов; `uid`/`version` — происхождение (объект, из
     которого прочитано); предел — 1 МиБ декодированных байтов (предел API на Secret
     целиком; в base64 ~1,4 МБ);
   - `PrepareValueEdit(req) → ValuePlan`, `RunValueEdit(run) → ValueResult` (решения 6–8).

   Все новые вызовы — со сроком (как `prepareEditTimeout` P9) и отменой вместе с сессией.
   HTTP-ответ `RevealValue` — с `Cache-Control: no-store`.

   `Values` отдельно от `GetResource`, чтобы ключи обновлялись вместе с ревизией и не
   смешивались с общими фактами.
3. **Показ.** Кнопка «Показать» у ключа: значение появляется в строке ключа (моноширинно,
   перенос; > 64 КБ — первые 64 КБ и «показать целиком»), рядом «Скрыть» и «Копировать».
   Небинарное — как текст; бинарное — base64 с пометкой «двоичное, N байт».
   Значение живёт только в состоянии секции деталей и **скрывается** при:
   - закрытии деталей, переходе к другому объекту, смене вкладки, вида или target-а;
   - смене ревизии объекта (показанное могло устареть): ключ скрыт, строка говорит
     «значение изменилось — показать снова»;
   - «Скрыть все».

   **Поздние ответы.** У каждого ключа — поколение запроса; «Скрыть», смена ревизии, уход и
   новый запрос того же ключа повышают поколение всей секции или ключа. Ответ `RevealValue`
   применяется, только если поколение то же, секция жива (проверка перед `setState`) и его
   `uid` совпадает с объектом деталей, а `version` — с ревизией, при которой спрашивали;
   иначе отбрасывается («значение изменилось — показать снова»). Последний запрос выигрывает.

   Показ и копирование — без подтверждения (это чтение, как в Lens), но только по явному
   действию над одним ключом; «показать все» нет.
4. **Копирование.** «Копировать» читает значение заново (`RevealValue`) и кладёт в буфер
   (desktop — Wails `Clipboard.SetText`, browser — `navigator.clipboard`), не показывая его;
   уведомление «значение ключа K скопировано» — без значения. Бинарное копируется как base64
   (сказано в уведомлении). Буфер обмена не очищается автоматически (это системный буфер
   пользователя; сказано в справке). Те же проверки живости и происхождения, что у показа,
   **до** записи в буфер: опоздавший ответ (детали закрыты, другой объект, новая ревизия) в
   буфер не пишется. **Буфер один на всё приложение**, поэтому у копирования — одно общее
   поколение (не по ключу): любое новое «Копировать» (в том числе другого ключа или объекта)
   делает все прежние устаревшими; ответ `RevealValue` устаревшего копирования отбрасывается.
   Записи в буфер идут строго по очереди (одна в полёте; следующая ждёт завершения
   предыдущей и перед записью снова проверяет, что она последняя), чтобы более старая
   системная запись не завершилась после новой. Тесты: Copy(A), затем Copy(B), ответы B→A —
   в буфере B; записи в буфер, завершающиеся в обратном порядке, — в буфере последнее. Уведомление — только после дождавшегося успеха записи; отказ записи —
   видимая ошибка. `term/clipboard.ts` не переиспользуется: его «успех» глотает ошибки.
5. **Где значение может утечь — и как нет.**
   - HTTP-транспорт browser-режима не логирует тела; `RevealValue` — обычный POST с
     bearer-токеном на loopback (как все методы).
   - Ошибки `RevealValue`/`Values` — через `secretSafe` (строки сервера о Secret не
     показываются). Туда же — **существующий** путь `GetResource` для Secret (сейчас
     `s.Get` Secret отдаёт текст сервера, например сообщение `Forbidden`): он в объёме P10,
     как и все остальные выходы чтения Secret.
   - UI не пишет значение в `localStorage`, `target_state`, недавние объекты, палитру,
     `title`-атрибуты и `aria-label`.
   - Go: значение — локальная переменная обработчика; объект после выбора ключа не
     удерживается.
   - Тест-ловушка: уникальная строка-маркер в Secret — и в декодированном виде, и в base64 —
     не встречается ни в одном ответе API, кроме `RevealValue`, ни в логе приложения, ни в
     SSE-событиях, ни в одной ошибке (каждый выход ошибки `Values`/`RevealValue`/
     `GetResource`/`PrepareValueEdit`/`RunValueEdit`, в том числе с маркером в ответе
     сервера) — Go (httptest) и e2e-kind.
6. **Правка ключа — диалог «Изменить значение».** Поля: ключ (для нового — ввод имени,
   проверка `[-._a-zA-Z0-9]+`, ≤ 253), значение — многострочное поле, режим «текст» или
   «base64». Операция явная: `set` (задать значение, в том числе пустое) или `delete`
   («Удалить ключ» — отдельная кнопка у ключа, тот же просмотр). Патч — `{"data": {K:
   base64(new)}}` или `{"data": {K: null}}`, с `metadata.uid` и `resourceVersion`.
   - **Байты сохраняются точно.** Режим «текст» только для значений без `\r` и корректного
     UTF-8 (`text`); значение с `\r`, иное бинарное — только base64 с пояснением («значение
     содержит CR — правка как base64, иначе поле ввода заменит CRLF на LF»). Ввод в режиме
     «текст» кодируется как есть (UTF-8 без нормализации); base64 проверяется. Тесты
     круговой передачи: CRLF, одиночный `\r`, завершающий `\n`, NUL, невалидный UTF-8, пустое.
   - **Нетронутое поле ≠ пустое значение.** Диалог существующего ключа открывается в
     состоянии «значение не загружено» (если оно не было показано): «Применить» недоступно,
     пока пользователь не подставит текущее значение («Загрузить текущее» — `RevealValue`) или
     не введёт новое. Пустое значение — только явным вводом (поле тронуто) и видно в
     просмотре («0 байт»).
   - **Жизнь подставленного значения.** Показанное значение, скопированное в поле, становится
     черновиком пользователя: смена ревизии скрывает показ в списке, но черновик не трогает
     (как текст редактора P9: полоса «объект изменился», просмотр покажет столкновение);
     закрытие диалога без правок — черновик уничтожается; с правками — `guard.ts`.
   - **Пределы ввода:** значение ≤ 1 МиБ декодированных байтов; введённый текст ≤ 1,5 МиБ
     символов (1 МиБ в base64 — ~1,4 МБ, плюс переводы строк: base64, разбитый на строки по 76
     с CRLF, принимается — `\r`/`\n` декодер пропускает; base64 строгий — лишние биты
     последнего символа отказ). Проверка до запроса (UI) и в API (до провайдера, отказ не
     цитирует значение); HTTP-транспорт принимает такое тело (тест).
7. **Просмотр правки (`PrepareValueEdit`)** — как P9, но без текстов значений:
   - где (context, сервер, namespace, вид, имя), ключ, операция: «N → M байт» / «новый ключ,
     M байт» / «ключ удаляется»;
   - dry-run (Secret — описанный вид: маршрут доказан, решение 7 P9), отказ — `secretSafe`;
   - `immutable: true` — недоступно до запроса («Secret неизменяемый: создайте новый»);
   - последствия: pod-ы, использующие Secret как переменные окружения, не увидят изменения
     до перезапуска; смонтированные тома обновятся с задержкой kubelet-а (кроме `subPath`);
   - **удаление ключа — всегда опасно** (красная кнопка, фокус на «Отмене»): потребителей
     Secret вне pod-ов (контроллеры, операторы, внешние системы) не увидеть. Поиск
     потребителей по `spec` pod-ов namespace-а лишь **уточняет** текст: `env[].valueFrom.
     secretKeyRef`, `envFrom`, `volumes[].secret` (с `items`), `projected.sources[].secret`
     (с `items`), `imagePullSecrets`, во всех контейнерах — обычных, init и ephemeral, с
     учётом `optional`; ограниченно, как связи P1. Запрет на список pod-ов, ошибка или
     усечение — «потребители неизвестны», никогда «потребителей нет»;
   - Secret с `type` `kubernetes.io/tls`/`dockerconfigjson`/`service-account-token` —
     предупреждение о формате, проверку делает сервер;
   - права — SSAR `patch secrets`;
   - изменилась ли версия с момента показа списка ключей (`rebased`), и если изменился этот
     ключ — **столкновение**, план опасный. Сравнение — по базе `Values`, а не по показу:
     база несёт для каждого ключа присутствие и **отпечаток** — HMAC ключом процесса от
     (маршрут, UID, ключ, байты), не голый SHA (конверт базы декодируем, а у короткого
     значения SHA перебирается). Столкновение: ключ изменился при той же длине, ключ
     появился (при добавлении), ключ исчез (при правке или удалении), пустое → удалён,
     удалён → создан заново; изменение **другого** ключа — только `rebased`. Всё — без
     `RevealValue`. Тесты — на каждый случай.
8. **Токены** — как P9 (решение 10): база `Values` связывает маршрут, UID, версию, `configRev`
   и отпечатки ключей (решение 7). Грант связывает **дайджест итогового патча**: HMAC с
   разделением доменов (`spk-ocular/value-grant/v1`) над канонической записью — маршрут
   (GVR, namespace, имя), UID, `resourceVersion` просмотра, `configRev`, ключ, операция
   (`set`/`delete`), присутствие ключа в базе и декодированные байты нового значения
   (длина-префиксные поля, без неоднозначной склейки). `RunValueEdit` заново строит патч из
   запроса, пересчитывает дайджест и пишет один раз с предусловиями; иное — отказ **до**
   PATCH. Тесты: грант `set ""` не принимает `delete` и наоборот; другой ключ, другие байты,
   другая версия или UID, другой `configRev` — отказ без запроса к серверу. Значение запроса
   не попадает ни в токен, ни в ответ.
   **Ожидаемый результат в гранте.** Просмотр вычисляет из ответа dry-run (или из точного
   локального наложения) ожидаемый набор ключей — для каждого присутствие и отпечаток
   (HMAC ключом процесса, как в базе). Подписанный грант несёт **сам** этот набор
   `{ключ, присутствие, отпечаток}` и `ServerChanges` (ключи, которые dry-run меняет иначе,
   чем введено); подпись гранта их аутентифицирует — так `RunValueEdit` без состояния
   называет ключи `Differs` и повторяет `ServerChanges`. Значений в гранте нет. Если ответ dry-run
   отличается от введённого (сервер или admission меняет введённые байты, другие ключи),
   просмотр говорит об этом без значений («сервер изменит значение ключа K», «…ключа L»).
   **После записи** Go сравнивает ответ записи с **этим** ожидаемым набором (не с базой
   `Values`: между показом ключей и просмотром другой участник мог законно поменять другие
   ключи): совпало — успех; нет — «сервер записал не то, что было в просмотре» по ключам, без
   значений (как `actual` в P9). Отдельно, если ожидаемое уже отличалось от введённого, это
   повторяется в результате. Без перечитывания, повторов и отката. Тесты: безобидная правка
   другого ключа до просмотра — успех без «изменено»; изменение той же длины при dry-run —
   предупреждение просмотра; ответ записи отличается от dry-run той же длиной — «не то»;
   ответ записи = dry-run, но ≠ введённому — успех с повтором предупреждения; другой ключ
   добавлен/удалён между просмотром и записью (admission) — «не то».
9. **Защита несохранённого.** Открытый диалог с изменённым значением участвует в `guard.ts`
   P9 (закрытие деталей, переходы — «Отбросить правки?»).
10. **Права и отказы.** Нет `get secrets` — детали и так не открываются (`forbidden`); нет
    `patch` — просмотр «прав нет», без гранта. `RevealValue` у удалённого/заменённого объекта —
    `gone`.

## Контракт

- `internal/core/values.go`: `ValueKey{Key, Size, Text}`, `ValueList{Ref, Version, Keys,
  Base}`, `Value{Key, Size, Text, Value, UID, Version}`, `ValueEdit{Ref, Base, Key, Op
  (set|delete), Value, Encoding (text|base64)}`, `ValuePlan{Where, Key, Op, Before, After
  (размеры, -1 — нет), Checked, Changed, Rebased, Collision, Destructive, Consumers (known|
  unknown, список), ServerChanges (ключи, которые dry-run меняет иначе, чем введено),
  Warnings, Rights, Unavailable, Token}`, `ValueResult{Message, Version, Differs (ключи,
  где записанное ≠ просмотренному), ServerChanges}`.
- `internal/provider/values.go`: `ValueHolder` с `Values`, `RevealValue`, `PrepareValueEdit`,
  `RunValueEdit`; `ValueBase` (маршрут, UID, версия, `configRev`, `{ключ, присутствие,
  отпечаток}`), `ValueGrant` (дайджест итоговой записи, ожидаемый набор `{ключ, присутствие,
  отпечаток}`, `ServerChanges`) — открытые поля, подпись в API.
- `internal/api/values.go`: методы, подпись (HMAC `revKey`), маршруты HTTP и Wails
  (`routes_test.go` проверит).
- `web/src/api`: типы и клиент; `web/src/values/` — секция деталей и диалог.
