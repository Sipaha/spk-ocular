# Спайк: тестовый Docker Engine (dind) под rootless docker, API Engine — 2026-09-30

**Вопрос.** Можно ли для тестов Compose provider-а поднять изолированный демон (как kind для
Kubernetes), не трогая демон пользователя, и как на деле выглядят API событий, логов и
статистики.

**Результат.**
- `docker run -d --name ocular-dind --privileged -e DOCKER_TLS_CERTDIR= -p
  127.0.0.1:23750:2375 docker:29-dind` под rootless docker пользователя (29.3.1) поднимается за
  ~2 с: Engine 29.8.1, overlayfs, cgroupfs; память контейнера ~90 МБ с шестью контейнерами
  фикстур. TCP без TLS только на loopback.
- Образы — без сети: `docker save busybox:latest | docker -H tcp://127.0.0.1:23750 load`.
- `docker -H tcp://127.0.0.1:23750 compose up -d` поднимает проект; labels
  `com.docker.compose.{project,service,container-number,oneoff,config-hash,depends_on,image,
  version,project.config_files,project.working_dir}` на месте (пути — хоста, где запускали
  compose).
- `_ping`: заголовок `Api-Version` (dind 1.56, демон пользователя 1.54).
- `/events?filters={"type":["container"]}`: строки JSON `{"Type","Action","Actor":{"ID",
  "Attributes"},"scope","time","timeNano"}`; атрибуты несут все labels. **Healthcheck
  порождает события `exec_create: …`/`exec_start: …`/`exec_die` на каждую проверку** и
  `health_status: healthy|unhealthy` — поток нужно фильтровать по действиям (`event` filter),
  иначе пересверка крутится на каждой проверке.
- Логи без TTY — мультиплекс: 8-байтовый заголовок (1 = stdout, 2 = stderr, длина big-endian),
  с `timestamps=1` строка начинается с RFC3339Nano и пробела.
- `stats?stream=false` отвечает за ~1 с (ждёт второй замер для `precpu_stats`) — пул и
  дедлайн обязательны.

**Решение.** Тестовый демон — `ocular-dind` (скрипты и цели make — P6 Task 0/4), мутации только
при endpoint-е `tcp://127.0.0.1:<порт dind>`.
