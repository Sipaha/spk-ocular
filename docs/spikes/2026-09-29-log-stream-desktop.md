# Спайк: fetch-стрим из desktop-окна к loopback-серверу (P2 Task 1)

Дата: 2026-09-29. Wails v3 beta.26, WebKitGTK (Ubuntu, Xvfb, без GPU).

## Вопрос

Можно ли в desktop-сборке читать лог-поток обычным `fetch` + `ReadableStream` со страницы
`wails://` к `http://127.0.0.1:<port>`: приходят ли данные по мере записи, нужен ли CORS,
не обрезается ли всплеск с последующей паузой (грабли launcher-а с `wails://`-мостом),
доходит ли отмена до сервера.

## Как проверяли

Временный код (не в репозитории): в desktop-сборке loopback-сервер на фиксированном порту с
ответами `stream` (строка NDJSON каждые 100 мс, `Flush` после каждой), `burst` (5000 строк по
~120 байт одним махом, пауза 3 с, ещё строка, пауза 2 с) и `report` (страница присылает
результаты). Страница при загрузке прогоняла сценарии и отчитывалась; запуск под
`xvfb-run`, итог — журнал сервера.

## Результат

| Сценарий | Итог |
|---|---|
| Origin страницы | `wails://localhost` (не `wails://wails`), `Host` — `127.0.0.1:<port>` |
| GET без `Access-Control-Allow-Origin` | `TypeError: Load failed` — CORS обязателен |
| GET с `Access-Control-Allow-Origin: wails://localhost`, простой запрос (без своих заголовков) | preflight нет; 20 чтений по одному кадру с шагом ~100 мс — поток живой, не буферизуется до конца |
| Всплеск 5000 строк → пауза 3 с → строка | все 5001 строки, последняя пришла через 3,0 с — обрезки нет |
| `AbortController.abort()` посреди потока | сервер видит `r.Context().Done()` сразу |

## Выводы для P2

- Поток логов — один запрос: backlog и follow в одном ответе безопасны (обрезка launcher-а —
  свойство `wails://`-моста, не loopback HTTP).
- CORS: `Access-Control-Allow-Origin` ровно для origin страницы desktop (`wails://localhost`);
  токен в пути, запрос «простой» — preflight не нужен.
- Закрытие вкладки = `abort` → запрос kube отменяется по контексту HTTP-запроса.
- Не проверено: поведение скрытого/свёрнутого окна (нет xdotool в окружении). Чтение идёт
  промисами `reader.read()`, не через rAF, поэтому остановки чтения не ожидается; обратное
  давление при остановке — предмет теста Task 2 на стороне сервера.
