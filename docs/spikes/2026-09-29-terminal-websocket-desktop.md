# Спайк: WebSocket из desktop-окна к loopback-серверу (P3 Task 1)

> Итог: работает без оговорок — WS годится для терминала; «толчок», как у fetch-стрима, не нужен.

Дата: 2026-09-29. Wails v3 beta.26, WebKitGTK (Ubuntu, Xvfb, без GPU), сервер —
`github.com/coder/websocket` v1.8.14.

## Вопрос

Можно ли из desktop-страницы `wails://localhost` открыть `ws://127.0.0.1:<port>` для терминала:
какой Origin приходит, ходят ли бинарные и текстовые кадры в обе стороны, какова задержка эха,
доходит ли большой вывод целиком и не придерживает ли WebKitGTK хвост всплеска (как у
fetch-стрима, см. `2026-09-29-log-stream-desktop.md`), как видны закрытия с обеих сторон и
перезагрузка страницы.

## Как проверяли

Временный код во временном worktree (не в репозитории): в desktop-сборке — WS-сервер на
фиксированном порту с маршрутами `echo`, `flood` (N байт кадрами по 32 КиБ, с окном 1 МиБ по
`ack`-кадрам страницы или без), `burst` (N байт разом, затем тишина при открытом соединении;
страница считает байты через 2,5 с), `serverclose` (кадр и закрытие 4001), `hold` (страница
перезагружается при открытом соединении). Страница прогоняла сценарии при загрузке и
отчитывалась POST-ом; запуск под Xvfb, итог — журнал сервера.

## Результат

| Сценарий | Итог |
|---|---|
| Рукопожатие | работает; `Origin: wails://localhost`, `Host: 127.0.0.1:<port>`; CORS для WS не нужен (Origin проверяет сервер) |
| Эхо 50 × 4 байта (бинарные) | p50 ≈ 0 мс, p95 4 мс, первый 67 мс (таймер WebKit грубый); текстовый кадр приходит строкой |
| 50 МБ без окна | все байты за 64 мс (страница только считает) |
| 50 МБ с окном 1 МиБ, ack каждые 128 КиБ | все байты за 126 мс, 80 ожиданий окна на сервере |
| Всплеск 2 МБ кадрами 32 КиБ, затем тишина | 6 из 6 — полностью |
| Всплеск 3 МБ кадрами по 200 байт, затем тишина | 6 из 6 — полностью |
| Закрытие страницей `close(4000, …)` | сервер видит статус 4000 и причину |
| Закрытие сервером 4001 после кадра | страница получила кадр, затем `close` 4001, `wasClean` |
| Перезагрузка страницы при открытом WS | сервер видит 1001 (Going Away) через ~0,3 с |

## Выводы для P3

- Терминал — WebSocket на сервере потоков (`internal/streams`), как в плане. Origin в
  рукопожатии desktop — `wails://localhost` (тот же `desktop.PageOrigin`), browser-режим — свой.
- В отличие от fetch-стрима, WebKitGTK не придерживает хвост WS-кадров: «толчок» не нужен,
  heartbeat — только для обнаружения мёртвой страницы (или полагаться на дедлайн записи и
  закрытие сокета).
- Транспорт сам по себе переваривает 50 МБ быстро; окно ack нужно не для WS, а для xterm, чей
  парсер медленнее сети, — его память и отзывчивость Ctrl+C под `cat` большого файла меряются в
  Task 9 на настоящем xterm.
- Закрытия с кодами проходят в обе стороны — кадр `end` + закрытие 1000 (или свой код 4xxx)
  надёжно отличимы от обрыва (1005/1006).
